# 第二大脑 · 风险验证原型

本地技术实验，不是正式知识库，不连接 AI 或 NAS。请只使用测试数据。

## 启动

在仓库根目录，使用 Node.js 24 与 pnpm 11：

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm check:build
pnpm preview:prototype
```

访问 <http://127.0.0.1:4173/>。开发模式：`pnpm dev:prototype`（开发模式不保证离线打开）。不要把监听地址改为公网或挂真实知识库。

## 可以体验

1. 修改 Markdown，等待“已保存本机”，刷新检查。
2. 进入思维导图，新增子/兄弟节点、修改标题和多行正文、添加关系、折叠、撤销和重做。
3. 点击同步，将浏览器副本存入测试服务；首次连接同名但内容不同会保守提示选择。
4. 构建预览首次联网打开后，等待“离线界面已安装”，重新打开让页面受缓存控制，再停止测试服务并刷新检查；此时仍可编辑并保存本机。恢复服务后手动同步。
5. 展开“验证工具与原始文件”，下载原文/草稿/冲突备份，恢复每约 30 分钟留下的 Markdown 本机历史点，或将当前原始文档移入回收站后恢复。

“模拟断网”只暂停同步调用，不等于浏览器真实断网。Ctrl+Z/Ctrl+Y 由 Markdown 编辑器支持；导图有独立撤销按钮，不跨刷新保留撤销栈。两个视图不会互相自动修改。

搜索默认排除 `raw/Archive/`，输入关键词后可勾选“包含归档”；正常文档浏览不隐藏归档。多个普通词按同时匹配，多个 `#标签` 也按同时匹配，可以混用；回收站条目不属于当前笔记列表，也不参与搜索。

侧栏可按 Inbox、Projects、Areas、Archive 过滤原始文档；文件名下方保留完整的父目录提示。实际路径不限制子目录深度，移动到新路径时可按需形成新的目录层级。选中一个非顶层目录后，可在“验证工具与原始文件”中将整个目录移动到新路径；它与单篇移动一样在一个事务中更新受支持的内部引用，拒绝覆盖和不明结构化引用。

打开有被引用的文档时，标题下会显示反向链接。它扫描本机 Markdown 中的 Wiki 与普通链接，并按照实际路径解析；失效链接、外部链接和私有 ID 都不会被误当作关联。

Markdown 顶部可添加 `raw/Projects/…`、`raw/Areas/…` 等软链接入口。它们写为可读的 `soft_links` Front Matter 列表，让一篇笔记有多个分类入口但仍只有一个真实文件；点击入口或浏览对应空间时会显示这些笔记，操作系统符号链接不参与知识库。

模板是 `raw/Areas/_templates/` 中普通 Markdown。可新建或编辑模板，再从侧栏选择模板创建一篇 Inbox 笔记；创建时复制原文，之后笔记和模板相互独立。模板管理文件不混入普通文档列表或搜索。

导图还可排序、缩进/提升子树、选择节点类型。点击节点后画布聚焦，Alt+↑↓ 排序、Alt+←→ 改层级；Ctrl/Cmd+Z 撤销，Ctrl+Y 或 Ctrl/Cmd+Shift+Z 重做。输入框使用原生快捷键；连续输入合并为撤销步骤，结构操作独立。关系端点随同名节点移动更新；导图撤销同时还原关系文件和选择，不跨外部同步替换去撤销其他端修改。

OPML 的额外单值文本头信息（作者、日期、自定义说明等）和文档/节点属性会随普通编辑保留。未知复杂 XML、注释、特殊声明仍明确拒绝；含未知路径语义的扩展字段可能使移动被拒绝，原文保留。窗口/日期元数据只保留，不自动重算；这不等于已验证所有 OPML 软件互通。

配套关系 YAML 中的手写注释会在编辑中保留；只修改节点正文时关系文件保持原样。节点改名或增删关系时只更新对应的 YAML 节点，删除的关系项所属注释可能一起移除；未知映射不猜测覆盖。

发生冲突时，Markdown 按片段二选一并保留其他修改；导图与关系文件保持成组一致。保存选择前自动备份双方，校验失败不会清空冲突。整组导图尚不做节点级自动合并。

更新构建前请同步或导出草稿、关闭其他旧版原型标签页，再重新打开。旧冲突会先备份再升级，无需清空站点数据；当前不支持新旧客户端同时写同一个浏览器库。

新版生产界面会先下载完整资源，显示“新版本已准备好”后等待全部旧标签页关闭；仅刷新不会立即升级。正在使用的界面固定到同一版 HTML/编辑器资源，不会主动刷新编辑中的页面。安装失败与笔记保存失败分别提示；不要为了更新清除浏览器数据。真实浏览器升级和从早期 Worker 迁移仍待验证，开发模式不受此策略保护。

移动/重命名会写入可读的 `state/moves.json`，同步时先处理旧路径再比较正文。OPML 正文与 URL、配对关系 YAML 的文件名也会更新。历史移动后的同名新建或目标占用无法确定归属时会停止，保留草稿；仅大小写变化的重命名暂时拒绝。

Markdown 链接重写使用解析器提供的位置；支持转义、标题、查询、锚点及部分 Front Matter 引用。遇到需更新但尚未支持的 HTML 或未知结构化引用，会取消移动并保留原文。支持移动重写不等于预览已支持完整 OFM 渲染。

阅读预览已支持 Wiki/普通库内链接、标题链接及折叠的 Front Matter 属性。库内链接在应用内打开；失效路径、失效标题和不支持的附件明确提示。属性错误不改原文；外部媒体不会自动加载。

独占段落的 `![[raw/Areas/主题.md]]` 展开正文，`![[raw/Areas/主题.md#标题|别名]]` 只展开该标题及下级小节。嵌入中的相对链接以来源文档为准；来源按钮可打开原文。句子中间的正文嵌入只显示“打开原文”链接。循环、失效标题或超限会提示，不改原文；单次预览最多嵌套 4 层、展开 24 次、累计解析 20 万字符的来源正文（标题引用也计整篇解析量）。不支持块 ID 或外部正文自动加载。

Markdown 编辑器上方可以选择本机图片、音视频或 PDF，原型单文件最多 1 MB、附件合计 4 MB/40 个、与文本合计 100 文件。支持 PNG/JPG/JPEG/GIF/WebP、MP4/WebM、MP3/WAV/OGG、PDF；文件保存到笔记同名 `.assets/`，原文插入可读路径。选择文件和插入引用一起保存本机，重名拒绝覆盖；随后手动同步。已有附件通过 `![[路径]]` 或 Markdown 图片语法预览；音视频不自动播放，PDF 只提供下载。解码失败仍保留原件。SVG/HTML 不作为活动媒体加载。

附件原件以二进制写入 `raw`，只有传输、IndexedDB 和恢复元数据使用 Base64。移动与离线对齐一起处理附件，附件冲突整文件二选一，可先分别下载检查。应急导出包含附件。尚未验证真实浏览器播放、存储配额/淘汰及大文件；小样本成功不等于完整媒体支持。

本版需同时更新并重启原型服务，关闭旧标签页后重新打开界面。含附件的知识库拒绝旧协议读写，首个附件事务将原型目录标记升级至 v2；不要使用旧服务降级打开。现有文本笔记无需清空。

支持 `==高亮==`、Obsidian 风格 Callout（含嵌套和折叠），以及 `$x^2$` / 独立 `$$` 公式块 / `math` 代码围栏。公式和字体都在本机处理，不使用 CDN；公式中的链接/图片/HTML 命令禁用。异常或过大的公式保留源码提示，普通代码与转义标记不变。可复制以下测试文本到新笔记体验：

```md
> [!note]- 核心结论
> ==先记录，再整理==。点击标题可展开或收起。

行内公式：$x^2 + y^2 = z^2$

$$
\frac{1}{2} + \frac{1}{2} = 1
$$
```

## 数据位置

- 服务端：本目录下 `.prototype-data/server/{raw,derived,state}`；已被 Git 忽略。
- 浏览器：当前 origin 的 IndexedDB `zfy-risk-lab-v1`；清除站点数据会删除未同步草稿。
- 测试夹具：`.prototype-data/tests/`；自动化测试使用新建隔离目录，不递归清理用户目录。
- “应急导出全部草稿”生成受版本约束的可读 JSON；“恢复应急草稿”只接受这一格式（原型界面文件上限 12 MB），并在覆盖本机草稿前创建本地恢复副本。恢复的是内容和附件，不会重放旧的同步/移动请求；恢复后先检查，再手动同步。

`localhost` 与 `127.0.0.1` 是不同浏览器 origin、各有本机存储。浏览器端 Markdown 编辑会最多每 30 分钟保存一次编辑前的粗粒度历史点；恢复前会将当前草稿放入本机恢复副本。回收站按文档 stem 保存 Markdown、导图、关系文件与附件，恢复拒绝覆盖新建的同路径文件。两者都是本机原型数据，未接入服务端同步、保留期或永久删除；请勿依赖它长期保存真实资料。

UTF-8 原文读取保留 BOM 文件头与 CRLF/LF 换行；移动、恢复和事务校验不吞掉这些字节。无效 UTF-8 会拒绝处理并保留文件，不进行编码猜测或自动替换。

## 三档恢复实验

以下命令只处理本原型 `.prototype-data` 下的测试副本，不提供整库备份创建、上传或定时备份：

```sh
pnpm --filter @zfy/risk-lab exec tsx server/restore-cli.ts --list
pnpm --filter @zfy/risk-lab exec tsx server/restore-cli.ts minimal .prototype-data/外部测试备份 .prototype-data/新的恢复目录
```

源目录由外部备份软件提供；最小档必须含 `raw`，标准档必须含 `raw`、`derived`。完整档额外复制实际存在的 `history`、`trash`、`config`、`state`、`manager`，排除 `cache`；缺少的目录会列在报告中。目标必须尚不存在，不允许覆盖、嵌套于源或经过符号链接。

完整档会在新副本内恢复已识别的事务，源保持不变。成功生成 `.restore-report.json`；失败保留现场和 `.restore-incomplete` 标记，正常初始化会拒绝打开。重新尝试需使用另一个新目录，不自动清理失败副本。恢复命令不启动服务、同步或 AI，也不改当前服务的数据位置；与旧设备重新配对尚未实现。

目前验证 UTF-8 原型内容及受支持 `.assets` 二进制夹具：最多 1000 个目录/文件项、50 MB 复制总量，正文/附件仍受上述提交限制。三档恢复都保留附件字节；未实现正式历史/配置的语义恢复或大文件恢复验收。没有外部文件清单时，无法证明源没有遗漏文件；目录散列复查不能替代暂停写入或一致性快照。浏览器未同步草稿不在服务端目录备份中。

## 自动检查

GitHub 的 `Prototype checks` 工作流在提交/PR 时使用标准 Ubuntu、Windows 运行器，执行锁定依赖安装、测试、构建和离线产物清单检查。仅给源码读取权限，不保存 Git 凭据，不部署服务、不上传原型数据；第三方 Actions 固定至核对过的提交 SHA。若仓库改回私有，工作流跳过运行器任务，避免未经确认消耗私有仓库额度。具体运行结果以 Actions 页面为准，配置存在不等于已经通过。
