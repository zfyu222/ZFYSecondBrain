# 整体架构与技术选型方案

状态：2026-09-02 技术设计基线，2026-09-03 已增加独立本地风险原型；用户已授权由实现方决定细节。原型仅覆盖部分候选与场景，不代表整体架构已验证。产品范围以 [Web 首版](../requirements/web-first-release.md)为准，实际进度见[原型验证记录](./prototype-validation.md)，完整标准见[验证与里程碑](./validation-and-milestones.md)。

## 1. 决策摘要

- 一套共享的 TypeScript 核心和 React 编辑界面：Web 先交付，Windows/安卓后续通过 Tauri 2 及平台适配接入。
- NAS 采用模块化单体知识库服务，不拆成大量微服务；AI 管理员单独进程/容器、可停用和替换。
- Markdown、OPML、YAML 与附件是真实知识来源；SQLite 仅保存可重建索引，运行与恢复必需状态另有明文记录。
- 服务端串行提交写事务，客户端先本地保存；使用共同版本和乐观并发检查，不做实时多人协同，不引入 CRDT 作为首版前提。
- 首版问答先用全文与关键词检索、链接邻域及原文读取；不先部署向量数据库、图数据库或 Redis。
- AI 框架优先验证 nanobot，通过独立适配器使用知识库工具；不让其默认工具和记忆机制接管原始文件。

## 2. 技术选择、用途与风险

| 层 | 设计选择 | 选择理由及待验证内容 |
| --- | --- | --- |
| 工程 | TypeScript；pnpm workspace 单仓库 | 共用格式、领域规则和客户端接口；不为每个平台复制一份业务代码。[pnpm workspace](https://pnpm.io/workspaces) |
| Web | React + Vite，静态 SPA，响应式布局 | 编辑型应用不需要 SEO/SSR；便于后续打包同一前端。[React 构建说明](https://react.dev/learn/build-a-react-app-from-scratch)、[Tauri 前端要求](https://v2.tauri.app/start/frontend/) |
| Markdown 编辑 | CodeMirror 6，源码编辑 + 渲染预览；不承诺首版 Notion 式任意块编辑器 | 保留原始文本，支持可扩展编辑；中文输入法、手机选区和撤销必须实测。[CodeMirror](https://codemirror.net/) |
| Markdown 解析 | Unified/Remark，延续已选 OFM 插件方向；渲染后白名单清理 HTML | 避免自造 Markdown 解析器；AST 用于分析，原始文本用于无损保存。插件组合兼容性仍需测试，见[格式文档](../requirements/markdown-format.md) |
| 导图编辑 | React Flow 开源核心；elkjs 为自动布局候选；独立 OPML/YAML 适配器 | React Flow 提供节点和连线交互，不是开箱即用的完整思维导图编辑器；需补树规则、键盘、正文、撤销和关系操作。[React Flow](https://reactflow.dev/learn/concepts/adding-interactivity)、[elkjs](https://github.com/kieler/elkjs) |
| Web 本地存储 | IndexedDB + Dexie；Service Worker 缓存应用静态资源 | 正文、基线与 outbox 在本地事务中保存；不依赖关闭浏览器后的后台运行。[Dexie](https://dexie.org/docs)、[Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API) |
| 原生壳 | Tauri 2；Rust 做系统适配；安卓控件用 Kotlin 原生组件 | 使用同一前端资源包，非仅加载 NAS 网页；可扩展原生插件，但不承诺所有插件在两端行为相同。[Tauri](https://v2.tauri.app/)、[移动插件](https://v2.tauri.app/develop/plugins/develop-mobile/) |
| 知识库服务 | Node.js 受支持 LTS + TypeScript + Fastify | 与客户端共享格式和校验；单服务处理文件、索引、同步、认证和工具入口。[Node 发布策略](https://nodejs.org/en/about/previous-releases)、[Fastify](https://fastify.dev/docs/latest/) |
| 索引 | SQLite + FTS5；通过独立存储适配器接入 | 不需独立数据库服务；中文短词单独处理；驱动、FTS 编译支持和 NAS CPU 二进制兼容须验证。[FTS5](https://www.sqlite.org/fts5.html) |
| 管理员 | Python 独立服务 + nanobot 适配器，候选待验证 | 复用 Agent 能力，不把其框架状态变成知识唯一来源。[nanobot](https://github.com/HKUDS/nanobot) |
| 部署 | 优先 Compose：知识库服务 + 可选管理员；NAS HTTPS 反向代理 | 群晖 Container Manager 的 Project 支持 Compose；具体型号可用性仍待核实。[群晖 Project](https://kb.synology.com/en-us/DSM/help/ContainerManager/docker_project) |
| 测试 | TypeScript 单元/契约测试 + 浏览器端到端测试；原生设备另测 | 拟采用 Vitest、Playwright；原生壳、中文输入法和桌面控件不能只靠桌面浏览器模拟验收 |

版本策略：原型阶段选相互兼容的稳定版并锁定确切版本，正式初始化时生成锁文件；本文不写未经实际构建验证的 patch 版本。依赖版本变更须重新跑格式和同步契约测试。

许可证与供应链门槛：核对实际发布包及其传递依赖、保留第三方声明、不依赖付费示例。特别是 elkjs 上游当前声明了 `EPL-2.0 OR GPL-3.0-or-later`，不能把它当作 MIT 依赖；最终以选中版本的许可证为准，发行前核对要求。[上游包声明](https://raw.githubusercontent.com/kieler/elkjs/master/package.json)。本轮不替用户决定项目对外开源许可证。

### 暂不采用的方向

- 三端分别重写：重复维护编辑器、格式与同步规则。
- 以 SSR 服务端页面作为编辑器核心：与离线运行和原生打包目标不符。
- 把导图 JSON/画布坐标作为唯一存储：违反 OPML/YAML 可迁移要求。
- Git 仓库作为运行时同步与历史引擎：首版需要细粒度冲突、附件和用户友好恢复，不要求用户管理分支；本项目源代码仍正常使用 Git。
- 先上独立向量数据库或图数据库：首版没有对应规模验证；预留检索接口即可。

## 3. 系统边界与代码复用

```text
共享客户端（React 界面 + TypeScript 领域逻辑）
├─ Web：浏览器存储、缓存与下载适配
└─ Tauri（后续）：原生文件、通知、安卓控件适配
          │ 同一版本化 API
          ▼
NAS 知识库服务
├─ 登录与权限、读取与搜索、同步与冲突
├─ 文件事务、路径重写、历史、回收站、索引
├─ 受控工具接口、任务记录与应用内通知
└─ 持久知识库目录
          ▲ 受限工具调用（不直接写目录）
          │
独立 AI 管理员
├─ 会话、模型调用、任务规划与 Skill
├─ 双视图、摘要、Inbox 整理工作流
└─ 唯一记忆整理调度器 → 可配置模型服务
```

计划的代码边界（仅目录设计，本轮不创建脚手架）：

- `apps/web`：Web 入口与响应式应用壳。
- `apps/native`：后续 Tauri 工程，引用同一界面包。
- `packages/ui`：Markdown/导图编辑器、列表、管理员入口。
- `packages/core`：格式模型、路径解析、确定性 diff、命令和校验；不导入 Node、DOM、Tauri 或模型 SDK。
- `packages/contracts`：API/工具运行时校验结构、错误码、版本约定；Python 管理员通过协议而不是复制 TS 内部对象通信。
- `packages/platform-web`、后续 `packages/platform-native`：本地保存、附件与系统能力。
- `services/library`：Fastify 入口及确定性领域服务。
- `services/manager`：Agent 适配、Skill 和工作流。

共享的是业务规则和大部分编辑界面，不是所有平台实现。文件持久化、触屏布局、系统权限、构建签名、通知和控件需要各自适配与测试。

安卓控件后续与原生本地存储层共享数据，不能依赖 App WebView 必须正在运行；轻量编辑 Activity 可直接保存并排入同步队列。该桥接必须在扩展原生端前验证。

## 4. 持久数据与备份

以下是设计目录，不是已经创建的用户知识库：

```text
知识库根目录/
├─ raw/                 # Inbox、Projects、Areas、Archive；原文与原始配套文件
├─ derived/             # AI 摘要、片段、关系及后续地图；不可视为可精确再生缓存
├─ history/             # 粗粒度恢复点、重要操作前后内容与来源清单
├─ trash/               # 删除内容、原位置及专属附件
├─ config/              # 用户设置、整理授权与服务器时间设置
├─ state/               # 同步基线/删除记录/移动记录、冲突、任务、通知、事务日志
├─ manager/             # 管理员会话与运行状态，不参与知识证据检索
└─ cache/               # 可重建 SQLite/全文索引、缩略图等；不存唯一未同步内容
```

- NAS 持久目录中的不可推导状态以有版本说明的 YAML/JSON/JSONL 和原格式快照保存；服务端数据库不能是授权、历史、基线或删除记录的唯一副本。
- Web 是平台适配例外：浏览器在 IndexedDB 中保存原格式文本和附件副本，并提供导出，不假装直接写入设备上的 `raw` 目录。尚未上传的新内容可能只有这个本地副本，必须保护，不能称其为可重建索引。后续原生端通过文件适配器保存开放格式目录。
- UI 临时节点 key、提交版本哈希、请求幂等键可以内部使用，但不是文档关系的地址；原始链接继续是路径和可读锚点。
- 原始文档的标签、收藏、视图开关等必须随 `raw` 迁移；字段归属与仅导图笔记的元数据在格式契约中明确，不偷放到数据库。模板也必须在 `raw` 内，不能成为第五种系统知识空间。
- “软链接”用可读目标路径的明文入口表达，不要求操作系统 symlink；真实 symlink 逃逸知识库根目录时服务端拒绝跟随。
- Markdown 保留原始字符文本；路径更新用语法定位的局部编辑，不每次保存都全篇序列化 AST，避免格式、注释和未知属性丢失。
- OPML/YAML 校验失败保留原文件，不自动重写成空文件。格式版本和未知属性的保留/拒绝编辑规则纳入测试。

### 三档备份的落地清单

| 档位 | 包含 | 不包含的恢复能力 |
| --- | --- | --- |
| 最小化 | `raw/` 全部实际文件，包括附件和模板 | AI 结果、历史、配置、回收站、同步状态 |
| 标准 | `raw/` + `derived/` | 历史、配置、回收站、同步和管理员状态 |
| 完整 | `raw/`、`derived/`、`history/`、`trash/`、`config/`、`state/`、`manager/` | 可排除 `cache/`；设备登录态和外部模型密钥可以重新配置 |

服务端密钥不发给浏览器、不提交 Git；以受限权限的部署配置/secret 提供，恢复内容不依赖它们。完整备份应提醒管理员会话及配置的敏感性。

系统只说明备份路径和安全暂停写入方式，不执行整库备份。恢复到新目录时先恢复未完成事务并校验；任意档位均不直接连回旧同步目标，缺少配置时不自动开启 AI。

## 5. 本地保存、同步与文件事务

### Web 本地保存

编辑命令先应用到本地模型，随后在同一 IndexedDB 事务中保存原格式内容、局部版本和 outbox 操作。只在事务成功后显示“已保存本机”。应用静态资源由 Service Worker 缓存，正文和授权 API 不走未经区分的通用响应缓存。

本地数据按服务器绑定隔离；多个标签页提交带本地基线版本，发现已有更新时重新比较，不用最后写入覆盖。自动清理只针对可重建/已同步缓存，未同步内容、冲突双方和必需基线不被淘汰策略主动删除。浏览器平台限制仍按[首版离线边界](../requirements/web-first-release.md)提示。

### 网络协议

首版采用 HTTPS JSON API + 变更游标拉取，打开应用/恢复连接时同步，在线时短轮询变化；长任务结果通过持久任务记录查询。实时广播不是正确性前提，后续可加 SSE 通知。

写请求至少带可读目标路径、来源版本、操作类型、客户端请求幂等键；创建须声明目标不存在。服务器返回提交版本或冲突，不用客户端时间戳判胜负。

公开接口按读取、搜索、变更计划/提交、变更拉取、冲突选择、历史/恢复、任务/通知分组。所有入口复用相同领域命令，管理员不能获得另一个绕过校验的写接口。

### 两类同步基线不能混用

- 设备同步：共同文件版本、本地改动、服务器改动。
- 双视图同步：上次已对齐的 Markdown、OPML、关系及对照信息；即使同一文件已上传，两个视图仍可能未对齐。
- 两边都修改时，从同一组快照计算双方差异，再生成合并计划；不能先把一边覆盖到另一边后重新 diff。
- 非重叠文本/结构操作可以确定性合并；无法可靠对应节点或段落的部分保留双方，进入冲突或待确认。AI 理解语义不等于允许自动融合冲突。
- 冲突选择携带当前冲突版本；旧设备的选择遇到新修改时再次检查。无冲突修改保留，不能因选择一个冲突项丢弃全篇其他更改。
- 双视图成功提交后才推进共同基线，记录来源以避免反向循环；部分待确认时不能把未解决部分误标为已对齐。

### 路径与删除

移动记录保存旧路径、新路径和对应提交版本。离线设备仍编辑旧路径时，只有可确认的移动链且目标版本可比较才重定位；不确定时保留冲突，不能重建出一篇旧路径副本。

删除显式记录，不以“没下载到文件”作为删除信号；旧客户端不应复活已删除内容。基线或游标过旧/缺失时先保留本地未同步内容并重新对账，不直接覆盖服务器。首版不自动清除历史、冲突、删除记录和移动链。

### 可恢复的多文件事务

1. 服务端串行写入，计算完整读写集合，校验权限、所有来源版本和目标冲突。
2. 保存前镜像、变更清单及暂存文件，持久化事务状态。
3. 进入短暂提交屏障；知识库 API 不读取半完成文件集合。完成文件替换、路径重写与配套移动。
4. 校验并持久记录提交；索引可随后重建。重试同一请求返回同一结果。
5. 中断后启动恢复流程：依据日志完成已提交事务或回滚未提交事务，完成前不开放受影响内容写入。

普通文件系统并不提供任意多个文件的天然原子替换；这是应用可见原子性与崩溃恢复方案，必须通过断电/进程终止等故障注入验证，不以一次 `rename` 或 SQLite 事务假装覆盖所有文件。

外部编辑器不遵守应用锁，无法承诺其看到同样的瞬时原子视图；发现提交期间的外部变化时保留双方、停止盲目覆盖和回滚。备份应暂停写入或使用验证过的一致性快照。NAS 原始目录使用监听加定期扫描，暂时读失败不能判为删除。

## 6. 搜索、来源与数据隔离

- 索引 Markdown 正文、OPML 标题和正文、标签、路径、显式引用；索引内的行号或 key 不写回原始链接。
- 中文全文使用 FTS5 trigram 作为子串召回候选；少于三个 Unicode 字符的查询不能仅用该全文查询路径，使用参数化子串查询/受控扫描兜底。`睡眠`、`AI` 和单字搜索必须有测试。[FTS5 trigram 限制](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)
- 搜索先过滤范围，再排序，避免 Archive、trash、历史、模板管理内容和管理员会话混入普通知识问答；用户明确扩大到归档/历史/回收站时标明来源类型。管理员会话始终不能成为正式知识证据，不能用“扩大范围”绕过这一原则。
- 原文片段带路径、标题上下文、原文摘录和来源版本；无标题/重复标题的定位方案在格式验证中确定。版本不匹配时明确显示来源已变，不能悄悄引用另一段。
- 摘要和关系帮助检索，事实回答仍需回读原文。派生内容依赖的来源被归档/删除后，不得通过缓存绕过默认排除；无法拆出有效来源时整个结果退出默认召回。
- SQLite 运行在 NAS 本机持久磁盘，不让多个设备通过 SMB/NFS 共同打开同一数据库；客户端经 API 访问。[SQLite WAL 对同机访问的要求](https://www.sqlite.org/wal.html)

## 7. 管理员接口、工作流与安全

### nanobot 适配门槛

优先验证 nanobot 而不是仅凭框架名称承诺可用。上游实现包含工具注册、会话与运行上下文等设施；必须验证能否只暴露本项目允许的工具并保持稳定任务接口。[上游运行实现](https://raw.githubusercontent.com/HKUDS/nanobot/main/nanobot/agent/loop.py)

- 管理员容器不挂载 `raw`、`derived`、历史和知识库密钥目录；只挂载自己的会话目录。
- 不开放通用 shell、任意文件写入、互联网搜索和任意远程 MCP 连接；工具清单由部署配置确定，不由笔记内容动态注册。
- 浏览器/调度器发起任务时，知识库产生与具体操作范围关联的授权记录；只读任务不能自行升级为写任务。管理员工具请求携带服务身份与任务授权，知识库服务再次校验。
- 首版先以版本化 HTTP/JSON 接口适配工具；nanobot 适配器负责包装。MCP 可以后加，但不作为知识库协议和可迁移数据的前提。
- 默认框架记忆、自动整理和重试行为都要审核：不能把对话变成正式知识，不能同时由框架和产品调度同一任务。
- 若无法稳定限制工具/权限或适配成本过高，仅替换 `services/manager` 运行器；保持工具契约。备选为薄的模型工具调用执行器，不重写知识库。

### 首批工作定义

按知识问答、受托编辑、双视图转换/同步、多级摘要、Inbox 整理分成五类工作定义。Skill 保存步骤和输出约束，工具处理可靠操作；首版不强制再拆多个子 Agent。

记忆整理只有一个服务端调度入口：按 NAS 配置时区 3 点运行；持久化运行记录以避免并发重复。文档级顺序为：检查冲突与版本 → 已授权双视图同步 → 摘要 → Inbox 归类/路径事务 → 保存结果与通知。派生文件保留来源版本，后续路径移动按事务更新引用。

任务不全库加锁：读取快照后释放锁，AI 运行期间允许用户编辑，写回时再次检查版本。重跑只处理未完成或来源变化的项。失败记录并通知、允许手动重跑；不开启无限自动重试。NAS 错过执行时间或运行中重启时显示错过/中断状态，不突然补跑未经用户预期的全库任务，下一计划周期正常运行。

### 简单但必要的安全

- 原文按既定需求明文存储；登录密码使用带盐的安全哈希，不能因“笔记不加密”把密码也保存原文。
- HTTPS 同源访问、受保护会话、CSRF/来源校验、基础限流；单用户不等于匿名开放。
- AI 只发送完成任务所需原文给用户配置的模型服务。NAS 自托管不等于原文绝不离开 NAS；设置里明确模型地址和发送边界，密钥不进入前端。
- 笔记、附件、检索结果中的指令一律视为数据，不视为用户授权；修改授权由服务端检查而非只靠提示词。
- Markdown/HTML 清理、链接协议白名单、XML 禁止外部实体/DTD、YAML 安全解析及大小限制；附件不能以可信应用脚本执行。
- 规范化路径、根目录约束、符号链接检查，禁止路径穿越和读取知识库外文件；单用户也需防止恶意附件/模型工具参数。
- Windows 大小写与保留文件名、Unicode 路径和 Linux 差异需在跨平台文件契约中处理；不能自动改名或压平用户目录来隐藏不兼容。
- 用户离线访问的是该设备已缓存的明文；服务端注销不能神奇擦除断网设备数据。退出时展示保留/清理影响，清理前保护未同步内容。

## 8. NAS 部署与待提供信息

优先一个知识库容器提供 API 和打包后的静态 Web，另一个可选管理员容器；反向代理统一 HTTPS 入口，内部工具不直接暴露到公网。不因 AI 故障阻止知识库健康检查通过。

容器使用非 root 运行和最小目录权限；知识库根目录绑定 NAS 持久路径。升级程序不覆盖用户目录，数据迁移先预检且可恢复。运行时/CPU 镜像组合在得知 NAS 型号后验证，不承诺所有群晖型号均支持。

远程连接优先利用用户已有的私有连接或受保护 HTTPS 入口；不自动开放 NAS 端口。外网验收需要用户届时提供 NAS 型号、DSM、CPU、内存、网络/证书条件和目标浏览器；模型服务和成本上限在 AI 阶段接入前明确。
