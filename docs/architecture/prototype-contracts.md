# M0 原型格式与接口契约

状态：2026-09-03，可执行实验契约 v1，不替代完整产品需求。代码在 `prototypes/risk-lab`，验证结果见[验证记录](./prototype-validation.md)。

## 1. 范围与数据归属

- 只处理独立夹具和 UTF-8 文本，不接入用户知识库，不接入 AI。
- 服务端目录：`prototypes/risk-lab/.prototype-data/server/`。首次启动必须为空或具有 `risk-lab-v1` 标记，拒绝接管已有目录。
- `raw/Inbox`、`raw/Projects`、`raw/Areas`、`raw/Archive` 支持任意层级；`derived/` 为预留加工目录。
- 同名 `.md`、`.opml` 配对；不要求同时存在。只有导图而没有关系时，不主动创建关系文件。媒体附件位于原文同名 `.assets/`，磁盘保留原始字节；文本附件仍按 UTF-8 处理。
- 浏览器 IndexedDB 存原文、共同基线、未完成请求和冲突恢复副本，不是可随意删除的缓存。服务端不能备份尚未上传的浏览器草稿。
- 开发热更新只监视工程源码，排除 `.prototype-data` 并禁用监听器软链接跟随，避免异常恢复夹具中的循环链接拖垮开发服务。该设置不是生产文件访问控制。
- `state/` 存事务日志和幂等请求账本，均为明文 JSON；当前无 SQLite。原始文件不依赖请求 UUID 或版本散列定位，它们仅用于事务与并发。

## 2. Markdown

编辑器直接保存字符串，不经过 Markdown AST 重新排版；服务端写 UTF-8。预览支持 GFM、Wiki/普通库内链接、标题定位和 YAML Front Matter 折叠属性；代码/任务列表/脚注由现成框架处理。解析只用于阅读，不将重排后的 AST 写回原文。属性错误单独提示，解析失败显示原文。

Wiki 语法使用 `@flowershow/remark-wiki-link@3.4.0`，显式路径由项目解析，不启用模糊全库 basename 匹配。普通和 Wiki 库内链接均在当前应用打开 `.md`/`.opml`；标题支持原文标题或可读 slug，重复标题的 slug 加序号。标题不存在、文档丢失、附件未支持时明确提示，不打开错误 HTTP 路径。标题改名的引用维护仍待实现，不能将只读定位视为改名维护完成。

Front Matter 使用 `remark-frontmatter@5.0.0`，支持 `---`/`...` 结束标记；值由现有 YAML 校验读取。渲染使用 `rehype-sanitize@6.0.0` 白名单，原始 HTML 跳过，禁止脚本/文件协议和绝对站点路径。外部 http(s)/mailto 链接需用户点击；新窗口带 `noopener noreferrer`。仅当前知识库已保存的受支持附件可以生成本机 Blob URL 预览；外部、伪造 blob/data URL 和未知媒体保留提示，不加载插件生成的 iframe。完整 OFM 尚未完成。

正文嵌入使用同一 remark AST：独占段落的 `![[路径.md#可选标题|可选别名]]` 展开整篇或对应标题至下一个同级/上级标题前的内容。嵌入不显示来源 Front Matter；标题选区保留文档范围的引用式链接/脚注定义。相对链接按来源路径解析，重复嵌入的标题、脚注和定义使用渲染时前缀隔离，不写入原文。句中嵌入退化为打开原文链接。来源导航与已有移动重写兼容。

展开上限为 4 层、24 次、累计来源 200,000 个 JS 字符；标题引用按整篇解析量计数。按来源路径和规范标题检测循环，缺失/错误/超限仅显示提示。所有嵌入共享主文档的公式预算及 HTML 安全策略；不抓取外部文档，不执行块 ID 或脚本。嵌入中的图片/附件同样按来源路径解析。仅验证静态渲染与原文不变，未完成实际浏览器布局/导航验收。

### 有界二进制附件实验

- 文件选择入口将附件和原文引用在同一 IndexedDB 事务中保存，不覆盖同名附件。引用仍为可读路径（特殊字符 URL 编码），不是对象 ID。
- 当前支持 `.assets/` 中的 PNG/JPG/JPEG/GIF/WebP、MP4/WebM、MP3/WAV/OGG、PDF；这是原型白名单，不是完整 OFM 格式范围。图片显示本机 Blob，音视频使用浏览器播放器 `preload="none"` 且不自动播放；PDF 只下载，不嵌入执行。解码失败保留下载入口。SVG/HTML 不作为活动附件加载。
- `attachments` 是独立路径映射，值为 `{ encoding: "base64", data }`；仅传输、浏览器存储和事务元数据使用 Base64，`raw` 下永远写回原始字节。禁止将同一路径同时作为文本和附件，也禁止将受支持媒体路径按文本提交。
- 单附件 1,000,000 字节，总计 4,000,000 字节、最多 40 个；文本和附件合计最多 100 个文件。临时使用完整快照，未实现流式/分块/断点续传、大文件配额或增量附件协议。
- 同一阅读预览（含正文嵌入）最多展开 24 处媒体、累计 8,000,000 原文件字节，重复引用也计入；超限显示提示。它限制 Blob 创建量，不等于图片解码后像素内存或播放器性能已受控。
- 相同字节视为相同内容，独立更改自动保留，双方修改/删除冲突为整附件二选一，不拼接二进制；确认前与文本冲突一起保存完整恢复副本。移动时一起迁移附件并重写受支持引用，目标占用拒绝。

Callout 使用 [@r4ai/remark-callout](https://github.com/r4ai/remark-callout) 0.6.2，支持自定义标题、类型、嵌套、`+` 默认展开和 `-` 默认收起；原生 `details/summary` 只改变阅读状态，不写回 Markdown。自定义类型使用通用样式，不执行自定义 CSS。适配层保护被反斜杠/实体转义的标记，保留普通引用。高亮使用 [remark-highlight-mark](https://github.com/shlroland/remark-highlight-mark) 1.4.0 的语法解析，适配其 `highlight` 节点为 `mark`，支持内部强调与链接，不通过全局正则替换原文。

数学使用 [remark-math / rehype-katex](https://github.com/remarkjs/remark-math) 6.0.0 / 7.0.1，配套 KaTeX 0.16.47（插件兼容的 0.16 系列）；支持 `$...$`、独立 `$$` 块及 `math` 代码围栏。先清洗普通标记，再允许 KaTeX 生成公式布局；[trust=false](https://katex.org/docs/options.html) 禁用公式中的链接、远程图片和 HTML 扩展，未配置跨表达式共享宏。字体本地打包，无 CDN。错误公式显示错误/源码而不丢失周围正文；单公式超过 8192 字符、超过 200 个公式或累计超过 65536 字符时保留源码提示，不继续渲染。另限制宏展开 1000 次、用户指定尺寸 20em；这些是原型阅读保护，不是正式文档容量限制或性能承诺。需要字面美元符号时可写 `\$` 或放入代码中。

阅读与标题提取共用插件管线，包含高亮、Wiki 别名和公式的标题保持一致。路径重写也启用同系列数学语法：公式内部看似 Markdown/Wiki 链接的字符不重写，公式外的实际引用照常更新。

依赖核验：实际安装的 Flowershow 4.0.0 发布包缺少声明的 `dist` 入口；已改用核对过发布文件、通过构建的 3.4.0，并锁定版本。上述新增插件及 `github-slugger@2.0.0` 的包声明均为 MIT；不等于已完成全依赖发行许可证审计。实现方向和上游链接见[格式文档](../requirements/markdown-format.md)。

当前两个视图分别保存，按钮“同步测试服务”只做设备副本同步，不做 Markdown/导图转换。双视图配置、仅导图笔记元数据、AI 共同基线和跨文档片段定位仍待实现，不能据文件存在直接认定用户授权 AI。

## 3. OPML 与语义关系

原型支持单根 OPML 2.0：`head/title`、`body/outline`；层级由嵌套确定，兄弟顺序由文件顺序确定。

| 属性              | 含义                                                                            |
| ----------------- | ------------------------------------------------------------------------------- |
| `text`            | 非空节点标题                                                                    |
| `type`            | 节点类型文本，默认 `topic`；UI 可选主题/标题/观点/例子/问题，已有自定义类型保留 |
| `zfyBody`         | Markdown 正文；属性中换行、回车、制表符使用 XML 数值实体                        |
| 其他 outline 属性 | 原样保留值，例如 `category`、`url`，暂不提供专门编辑 UI                         |

保存会规范化 XML 排版，但不应改变受支持内容。支持额外的单值文本 `head` 字段（例如作者、日期、窗口状态、自定义描述），以及文档/节点的扩展属性和限定名称；值原样保留，不作为指令执行。对象原型同名属性也作为自有数据处理。处理方式参考 [OPML 2.0 规范](https://opml.org/spec2.opml)，不代表已经通过其他软件的实测导入/导出。

嵌套、重复或带属性的额外 head 元素、未知 body/outline 子元素、DTD、实体声明、注释、非 UTF-8 或无法保留的 XML 声明仍拒绝读取/提交，不会静默删除后覆盖。仍需唯一文本标题和单根节点，不是通用 OPML 导入器。日期/窗口/展开状态只保留、不更新其语义，因此不能假定它们仍描述编辑后的布局。

移动时 `docs`/`ownerId` 按 URL 字段重写，作者邮箱、名字、日期等明确的非路径字段保持原值；其余未知头字段或文档属性若含受影响引用，则取消移动，等待明确 schema。普通编辑不会因为不了解字段含义就将它删除。

节点路径使用标题，加同名兄弟中的一基序号，例如 `/健康[1]/睡眠[1]`。所有节点都带序号，避免首次出现同名节点时更换编码。标题中 `~ / [ ]` 分别转义为 `~0 ~1 ~2 ~3`；路径区分大小写。重命名、重排会重写当前图的关系端点；被删除节点的关系随删除操作移除，图内撤销可恢复。

关系 YAML 编辑使用现有 [yaml 文档节点接口](https://eemeli.org/yaml/#content-nodes) 保留注释：只改节点正文且关系未变时，返回原始关系文本，不重排或规范化。端点改名、增加/移除关系时复用明确对应的 YAML 节点，保留剩余项与文档注释、标量引号和 CRLF；删除关系时其所属注释可能随该项移除。编辑过程中的来源序号只用于本次操作，不写入原文或作为文档 ID。未知来源、重复来源或结果校验失败拒绝保存，不能按相似文字猜测对应关系。复杂未知 schema 仍拒绝，而非任意 YAML 编辑器。

导图增加上移/下移、缩进为前一个兄弟的子节点、提升至父节点之后；子树整体移动，根节点不能移出，首尾无效操作禁用。移动/改名按本次编辑中的对象对应关系更新语义端点、选中状态和折叠路径，不在原文引入 ID。新增后选中新节点，删除后选中父节点；选中节点移入折叠分支会展开其祖先。保存前重新校验 OPML/关系，超限或无效结构不保存。

画布聚焦时支持 Alt+方向键调整结构；Ctrl/Cmd+Z 撤销，Ctrl+Y 或 Ctrl/Cmd+Shift+Z 重做。输入框保留原生编辑快捷键，组合输入不触发画布命令；Tab 不被截获。结构操作单独留撤销点，标题/正文在同一次聚焦且间隔不超过 750ms 时合并连续输入；内存最多保留 100 个撤销点，不是持久文档历史。撤销同时恢复导图、关系文件是否存在、选择与折叠状态；外部内容替换后旧撤销链失效，不覆盖其他端新内容。仍未验证真实 IME/触屏和 500 节点交互性能。

```yaml
version: 1
map: ./健康.opml
relations:
  - from: /健康[1]/睡眠[1]
    to: /健康[1]/恢复[1]
    type: 影响
    status: confirmed
```

关系字段严格校验；`map` 必须是当前同名 OPML 的相对文件名，端点必须存在。YAML 禁止重复键与别名。内置 15 种关系及方向沿用[双视图需求](../requirements/dual-view-notes.md)，`unresolved` 使用虚线。当前只支持图内端点，自定义关系可保留文本，但 UI 尚无创建入口。跨文档关系 schema、双向关系去重仍待补齐。

## 4. 路径与移动

- API 使用 `/`，限定在 `raw` 四空间或 `derived` 内；禁止绝对路径、`..`、反斜杠、Windows 保留名、尾随点/空格和事务临时文件后缀。
- 检查大小写及 NFC 等价重名、文件与目录冲突；当前不会自动改名规避冲突。
- `.md` 移动带同名 OPML、关系 YAML、元数据 YAML 和 `.assets/` 文本夹具。支持保持文件名移动目录和重命名；关系 YAML 的 `map` 字段随文件名更新，OPML 节点正文和 `url/htmlUrl/xmlUrl` 属性按已支持的链接规则重写。
- 受支持链接：显式相对路径或 `raw/...` 路径的普通 Markdown 链接、图片目标、引用式定义、Wiki 链接和嵌入。使用 micromark 的具体 token 位置修改目标，而非查找/替换整段字符串；支持标题重复、转义、字符实体、GFM 表格、查询参数与锚点。保留别名和其余正文，跳过代码、转义 Wiki 语法与链接标题；移动所有者时调整相对引用。
- Front Matter 支持显式 Markdown/Wiki 引用，以及 `url/cover/image/video/audio/attachment/links/references` 字段中的路径（包含列表）。变更时通过 YAML 文档模型保留值和注释，可能规范化元数据排版；正文不重排，无变更时保持整份原文。别名/重复键、未闭合头部、未知字段的裸路径引用会明确拒绝。
- **不是完整 OFM 引用维护**：隐式全库同名查找、HTML 资源重写、未知 OPML 属性和派生图谱 schema 尚未完成。发现需要更新的 HTML `href/src/poster/srcset` 时取消移动；未知 YAML/JSON 字符串或 OPML 属性中发现可识别的路径/Markdown/Wiki 引用也会拒绝。无法识别的自定义语法仍可能遗漏。
- 仅大小写或 Unicode 等价的重命名、目录拼写别名目前明确拒绝；不把 Windows 上的同一路径误当两个文件。提交前检查现有路径，落盘后复核原文快照。
- 不能接真实资料、不能开启每日自动移动。可读移动链与旧路径提交已完成下述原型协议，仍不代表完整路径/附件/恢复验收通过。

### 可读移动记录 v1

`state/moves.json` 保存 `{ version: 1, records: [...] }`。每条记录包含连续 `sequence`、原始 `from`、目标 `to`、时间 `at` 和实际源文件路径 `paths`。这些都是可读路径，不是文档 ID。移动记录与文件、幂等回执受同一事务日志保护，重试不追加重复记录。

快照增加 `moves` 数组；客户端保留已观察的记录前缀。同步前把共同基线和本机草稿依次重放至新路径，再进行三方比较。离线删除保持为删除；离线新增的同名视图/附件也一起移动；已观察过的旧路径被用于新文档时，不会再次重定向。无法确认归属的同名新建、目标被占用、记录缺失/分叉会停止并保留本机草稿，暂不猜测修复。

移动返回原路径时，文件内容可能恢复原样，但版本仍包含不同的移动记录，防止误认旧基线。客户端提交 `moveSequence` 表示已处理的移动记录数量；服务端在同一提交锁内检查，不一致返回 409。旧客户端缺少该字段按 0 处理，有移动记录后不能据当前内容版本直接覆盖。历史记录暂不压缩/清理。

旧协议上线前发生的移动无法自动补出记录，不从内容相似度猜测迁移。还原不含 `state` 的备份后，旧客户端若持有缺失的移动记录会停止；备份恢复时的重新配对流程仍待实现。

## 5. 本地测试 API

仅监听 `127.0.0.1:4173`，校验 Host/Origin，无用户认证、无公网暴露。所有响应为 JSON；静态页面和 API 同源。

| 接口                | 输入 / 输出                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------ |
| `GET /api/health`   | 原型运行信息                                                                                           |
| `GET /api/snapshot` | `{ revision, files, moves, protocolVersion?, attachments? }`；有附件时要求请求头 `X-Vault-Protocol: 2` |
| `POST /api/commit`  | `{ protocolVersion: 2, requestId, expectedRevision, moveSequence, files, attachments }` → 新快照       |
| `POST /api/move`    | `{ protocolVersion: 2, requestId, expectedRevision, from, to }` → 新快照                               |

`revision` 是排序后文本、附件及移动记录的 SHA-256；无附件时保持旧散列兼容。提交是**完整内容快照**，缺失路径表示删除，不能把它误当局部 patch。正文单文件 200 万 JS 字符、总计 500 万字符；附件另有上述限制，HTTP body 合计上限 1200 万字节（JSON 转义/编码后仍可能先到达传输上限）。正式增量协议待实现。

无附件旧快照继续可读；有附件时客户端必须声明 v2 并完整提交 `attachments`，遗漏字段或旧版写入明确拒绝，不能静默删除附件。首次二进制事务先将磁盘标记升级到 `risk-lab-v2`，不降回 v1，旧版服务应拒绝打开。浏览器数据库升至 schema 3；原型客户端仍要求关闭全部旧标签页后升级，不宣称完整跨版本隔离。

- 共同版本不一致：HTTP 409，返回当前快照；不自动覆盖。
- 输入/schema 或移动前置检查拒绝：400；Host/Origin 拒绝：403；正文超限：413；不支持的请求媒体类型：415；未声明附件读取能力：426。
- 其他错误：500，结果可能尚未确认，保留请求重试。
- requestId 至少 8 字符；同一请求重试返回原结果，不能复用到不同内容。客户端先把请求和 payload 存到 IndexedDB，再发送；移动同样如此。
- 本机另一标签页写入时按本地版本拒绝旧写入，不以最后写入覆盖。确认操作从数据库重新读取当前冲突计划，不信任已过时的界面副本。
- **Markdown 按冲突片段二选一**：有共同基线且双方文件都存在时，按保留换行的行序列做三方比较；自动保留双方无重叠修改，只选择发生冲突的片段。同一文件可有多个独立选择，空片段表示删除这些行，不是删除整个文件。没有共同基线的同名新建、删除对编辑仍按整文件选择。同一行内的不同词修改不会强行按字符合并。
- **OPML 与同名关系 YAML 是一个一致性组**：整组未变的一方让位于已改的一方；不同组件的单边修改只有在合成后通过端点和 schema 校验时才自动保留。否则只提供一个整组二选一，不能将两端文件分别选取。删除组也不会留下孤立关系文件。
- 目前不对两份都修改了的 OPML 进行节点级自动合并，也不对 YAML 逐行合并；整组选择可能舍弃组内另一方的修改，但完整双方仍留在恢复副本中。其他文档及 Markdown 的非冲突片段不受这个选择影响。图内字段级合并仍未实现，不据此宣称 V2 全量通过。
- 保存选择前校验整个结果，随后在同一 IndexedDB 事务中保存双方和基线的恢复副本、替换本机文件、清空冲突。缺少选择、旧标签页提交、schema 失败或写入失败都会保留原冲突；失败事务不留下虚假的成功恢复点。提供恢复副本导出，尚无导回 UI。

### 本机冲突计划 v2

`conflict.formatVersion: 2` 与服务器 API 版本独立。`baseFiles` 保存检测时的真实共同基线，`merged` 保存自动合并的文件，`items` 保存三种项目：

- `text`：原始双方/基线，以及由固定文本和可选择片段组成的 `parts`。选择键仅在这份计划内定位片段，不写入原始 Markdown。
- `graph`：两个文件路径及双方/基线的整组文件映射，缺失键表示文件不存在。
- `file`：新建/删除或其他无法拆解的整文件冲突。

无版本号的旧冲突在首次读取时先备份，再从保留的原文和基线重新生成计划、增加本机版本号；重复读取不重复升级。未知未来版本停止读取，不猜测降级。不修改原始文件格式，不需要清空浏览器数据。

附件分支另存于同一冲突计划的 `attachments`（自动保留部分）和 `attachmentItems`（双方/基线），与文本选择在同一事务中确认。应急导出包括全部附件编码；尚无导回 UI。

应急草稿导出格式固定为严格的 `{ protocolVersion: 2, files, attachments }`。恢复只接受该完整形状，先校验路径、文本、附件编码和合计限额；覆盖本机草稿与写入其恢复副本属于同一个 IndexedDB 事务。导入不携带服务端基线、未确认提交、移动请求或冲突计划，因此不会重放过期网络操作；恢复完成后必须由用户手动发起同步，并可能按正常规则产生冲突。

**升级使用约束**：先同步或导出草稿，关闭其他旧版原型标签页，再载入新构建。仅提高数据库版本不能保证旧代码拒绝访问；当前不支持新旧客户端同时写同一浏览器库，完整跨版本写入隔离仍待实现。

## 6. 事务与恢复

文本读取使用严格 UTF-8，并保留文件头 BOM 和原有换行，不在读取时规范化原文。BOM 计入内容散列，提交校验、移动及三档恢复使用同一规则；Markdown、OPML 和关系 YAML 的解析器仅在解析输入时跳过文件头标记，不改写源文本。无效 UTF-8 拒绝打开，不以替换字符猜测修复。旧日志如果与实际字节不一致，仍保留现场并停止，不自动重写散列。

服务单进程串行提交：校验 → 记录 prepared（前后快照、前后账本）→ 临时文件写入/fsync/rename → 更新账本 → committed → 移除日志。

同一 Node 进程中的多个 `FileStore` 实例按规范化绝对目录共享队列，Windows 大小写别名共用队列。初始化、快照、提交、移动和公开恢复入口均排队，不能在另一个实例提交途中擅自回滚它的日志。空闲队列释放；失败不阻塞后续恢复。路径预检会在准备日志前拒绝把现有目录当成文件覆盖。此保护不覆盖不同进程、Worker/模块副本、所有文件系统别名或外部编辑器，仍不是操作系统文件锁。

原型服务先绑定固定本机端口，再初始化/恢复知识库；端口被占用则关闭新建服务资源，不调用存储初始化。初始化期间返回 503/no-store，成功后才开放 API；失败关闭监听器。这样避免正常重复启动同端口服务时先动到运行中的日志，不代表任意多进程或不同端口访问已受到文件锁保护。

启动、读快照和提交前均恢复：prepared 回滚，committed 保持提交结果。正文、二进制字节、移动记录和回执一起恢复；若文件或记录不匹配事务前后任一状态，保留现场并停止。二进制事务使用日志 v2，兼容旧文本日志 v1。已在 prepared、文件应用、回执、移动记录、committed 五个边界注入异常并验证重启；检测不是操作系统文件锁，也未证明物理断电、目录 fsync、多进程并发或全部磁盘失败场景。

账本暂不清理，不等于正式历史/回收站；完整备份需包含它。恢复前严格检查日志版本、状态、快照内容/散列及账本结构；未知状态不当作 prepared 猜测处理。v1 散列依赖原始 JSON 文件键序和移动记录属性顺序，校验保留存储时的对象顺序，不按接收机器的 locale/ICU 重新排序，以保留既有回执兼容性。账本逐个校验所有自有条目，包括原型链同名键；不把继承属性当成回执，也不因通用对象规范化静默丢掉重试记录。尚未提供自动恢复导入界面，也未实现自动清理。

初始化检查根目录的既有祖先路径；原型标记、运行账本/日志和写入临时文件拒绝符号链接、特殊文件与多重硬链接，防止写入影响另一个路径下的文件。失败保留现场，不自动删除可疑临时文件。这些是操作前检查，不能抵御检查后由另一个进程替换路径，仍不是操作系统级锁或完整安全审计。

### 三档外部副本恢复实验

`server/restore-cli.ts --list` 输出三档范围：minimal=`raw`；standard=`raw+derived`；full 额外包括实际存在的 `history/trash/config/state/manager`，排除 `cache`。没有内置备份创建、调度或上传功能。

`restorePrototype` 仅接受 `.prototype-data` 内的新独立目标，不覆盖已有目录或接管当前服务。源只读，拒绝路径重叠、符号链接、未知完整备份根目录项及超限数据；复制前后清点并比较文件散列。最小/标准档重新初始化未备份的运行状态；源有未完成事务时必须使用完整档。完整档只在新副本恢复事务；未知格式、损坏散列、孤立临时文件或不支持的原文停止处理。

恢复中写 `.restore-incomplete`，失败保留现场并阻止正常初始化；成功才写 `.risk-lab` 和 `.restore-report.json`、移除未完成标记。报告列实际包含/排除/缺少目录、事务恢复情况和限制。不启动同步、服务或 AI，不复用当前服务数据目录；正式重新配对流程仍待实现。

当前验证 UTF-8 原型文件及上述 `.assets` 二进制夹具（复制上限 1000 项、50 MB，raw/derived 另有提交限制）。三档均保留附件原始字节，完整档可在新副本恢复未完成的附件事务；不支持的二进制原文仍拒绝。其他管理目录仅保留字节，不宣称未来历史、配置或 AI 框架已语义恢复；凭据也不自动启用。没有外部源文件清单，无法识别备份之前就遗漏的文件；前后复查不保证运行中逐文件备份的一致性，必须暂停写入或使用已验证的快照。未验证真实大文件/媒体解码、NAS、物理断电或全库恢复 UI。

## 7. 兼容性约束

收藏状态采用 Markdown 顶层 Front Matter 中的明文 `favorite: true|false`，不使用数据库 ID 作为唯一来源。切换收藏只改该标量并保留 BOM、换行和同一行注释；没有 Front Matter 时添加最小 YAML 块。Front Matter 未闭合、非对象或 `favorite` 非布尔值时停止修改，不能猜测或覆盖用户元数据。导图专属笔记暂不显示收藏开关。

最近文档是本机 IndexedDB 中的可读文档 stem 与 ISO 时间戳，不修改笔记正文或充当文档 ID。每次打开、创建或 Markdown/OPML 文档移动都会更新或迁移该入口；界面忽略已不存在的路径。当前原型不将它跨设备同步，完整版本再以可迁移的用户状态设计补齐。

两个编辑器和阅读视图按需分包，加载失败隔离在各自区域，其他草稿导出/状态界面仍保留。生产构建额外生成带内容散列的 HTML 入口；Worker 缓存清单包含该入口、全部 JS/CSS 和公式字体，`pnpm check:build` 核对入口内容/散列和全部资源，并检查 CSS 中的每个非内联 URL 已缓存；API 和原始文件不进入界面缓存。离线缓存仍会下载所有分包和字体，拆包不等于降低完整离线安装的总下载量。

Worker 遵循默认等待期，不调用 `skipWaiting` 或 `clients.claim`。安装时保留旧缓存；只有激活时清理其他 `risk-lab-` 界面缓存，不接触 IndexedDB。受控的根页面导航始终使用当前 Worker 对应的不可变 HTML；缓存丢失仅请求该版本入口，失败返回 503 与保留草稿提示，不回退到部署后可能已变更的 `/`。版本化入口缺失会使安装失败，而不是混装另一版本。

界面监听安装/等待/失败状态，新版本等待时提示确认本机保存（失败先导出），关闭此应用全部标签页后重开。不强制刷新，不将界面安装失败报告成笔记保存失败。此策略参考 [Service Worker 生命周期](https://web.dev/articles/service-worker-lifecycle)；目前只有模拟生命周期和构建产物测试，未完成真实浏览器升级验收。首次未受控页面、开发模式、旧 Worker 迁移和后端兼容仍需独立保护，不能替代客户端写入版本隔离。

协议只适用于本原型；变更须同步更新 schema、测试和本契约。正式版不能直接认领原型数据目录。目前仅有上述本机冲突计划的定向升级，没有通用原始数据迁移器；进入 M1 前需独立制定迁移与未知字段保留方案。
