## 3. 实际浏览器检查

使用本机浏览器打开构建后的应用，不以第三方框架演示页替代。

- Markdown 编辑并出现“已保存本机”后刷新：原文仍存在。
- 导图输入两段正文和 emoji，新增子节点、撤销，再刷新打开：正文和结构保存正确。
- 首次无共同基线，服务端与本机同名内容不同：明确提示冲突；选择本机后保存，再次同步成功。
- 移动 `raw/Inbox/开始使用.md` 至 `raw/Areas/开始使用.md`：UI 报告成功；原型说明中的入站 Wiki 链接同步改为新路径，核对服务端原文一致。
- 关闭本轮启动的测试服务后刷新：已缓存界面仍打开，原有本机 Markdown 可读取。随后重新启动服务。
- 桌面截图检查：侧栏、双栏编辑/预览、同步状态和验证工具可见。
- 390×844 窄屏检查：布局切为上下编辑/预览，同步按钮可见，页面 scrollWidth 与 clientWidth 均为 390，无整页横向溢出；不代替安卓真机验收。

本轮新增浏览器验收（独立生成样本，不修改已有示例）：

- Markdown 双方都修改中间段，同时分别修改开头和结尾；选择服务端中间段后，双方独立段都保留，核对服务端实际落盘原文一致。
- 未选冲突项即保存：页面明确拒绝，不清空待处理状态；完成选择后可以保存并同步。
- 本机改名导图节点并更新关系，服务端修改关系类型：只显示一组两个选项，而不是两个文件各自选择。
- 刷新页面后该冲突组仍在；选本机组并同步，服务端 OPML 与 YAML 的新节点路径一致，未混入旧端点。
- 本轮页面检查未捕获 JavaScript error 日志。浏览器使用同一客户端，服务端另一侧修改由隔离夹具脚本构造，不冒充两台真实设备测试。

复现入口：`pnpm --filter @zfy/risk-lab exec tsx tests/browser-conflict-fixture.ts base 唯一英文测试标签`，界面同步并修改对应样本后，用同一标签执行 `remote` 阶段制造另一侧修改。脚本仅接受本机原型服务，保留其他文件；拒绝覆盖已存在或发生额外变化的样本。

未使用系统级断网，服务不可用刷新测试不等于浏览器全网络离线、首次离线安装或移动端缓存淘汰验收。中文字符输入不等于真实中文 IME 组合输入验收。测试写入的示例留在忽略目录/本机测试存储中，未进入 Git。

特别限制：Markdown 采用行序列形成的冲突片段，不做字符级合并；导图/关系保持成组一致，但尚未做图内节点/字段级合并。组内另一分支的修改可能只保留在恢复副本中；完整双方可导出。缺失共同基线、删除对编辑保持保守选择，未引入 AI 合并或进阶 diff 查看器。

版本测试还发现：仅增加 Dexie 数据库版本不能保证旧客户端无法重新打开，因此没有把它当作写入隔离方案。现在的生产 Worker 不再跳过等待期或接管未受控页面；根导航固定使用同构建的不可变 HTML，不从可变的 `/` 混入新代码。更新提示要求先保存/导出，再关闭全部原型标签页重开；不刷新正在编辑的页面，不删除 IndexedDB。

这只是生产界面升级策略的模拟生命周期与构建产物验证，不是完整客户端版本隔离。首次未受控页面、开发模式、旧版 Worker 向本版迁移、浏览器强制更新/缓存淘汰、后端协议及真实新旧标签页仍待验收。升级前须关闭旧版标签页，不能宣称所有版本可并存写入。

外部进程可以在版本检测之后写入文件，当前没有操作系统级排他锁。因此不得直接让外部编辑器和原型服务并发管理真实原文。异常注入测试仅证明已列出的回滚分支，不证明物理断电一致性。
