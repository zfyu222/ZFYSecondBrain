# 首版执行计划表

更新时间：2026-09-09。执行顺序固定为：本地实现 → 本地自动化测试 → 本机浏览器复测 → 远程只读/临时数据验收。

## 目标

首版先交付一个可自托管的 Web 知识库：Markdown 与思维导图可以独立编辑、按共同基线增量同步；离线草稿、冲突选择、附件、移动/恢复和管理员受控 AI 不丢数据、不越权。

## 当前继续执行顺序

1. **本地稳定性收口**：优先补齐可自动验证的格式往返、双视图增量合并、冲突和恢复边界；每次改动后执行 `typecheck`、`test`、`build`、`check:build` 与浏览器 smoke。
2. **本地体验收口**：检查窄屏、键盘操作、错误提示、离线草稿和导出/恢复入口；不在此阶段引入未经验证的全量 OFM 或复杂图谱自动合并。
3. **本地 AI 回归**：使用已配置的 OpenAI 兼容模型适配器验证“只读检索 → 候选 → 管理员审阅 → 版本化写入”链路；密钥只读环境变量，不写入仓库、日志或浏览器。
4. **远程最终验收**：本地门槛全部通过后，才在测试服务器执行健康、登录、第二客户端读取、附件预览/回收、持久化和受信域名代理检查；只使用临时测试数据并清理。

## 明确暂缓范围

- 完整 OFM/跨软件导图兼容、复杂图谱字段级自动合并。
- Windows/Android 真机壳、真实移动播放器和多设备网络条件。
- 生产级备份编排、长时间定时任务观测和大文件流式增量协议。

这些项目保留在后续版本，不作为首版已完成的依据；若要纳入首版，必须先增加对应夹具、失败注入和真实设备/服务器验收证据。

## 每次提交的最小证据

- 变更对应的单元/API 测试或浏览器 smoke。
- `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm check:build`。
- gitleaks 扫描无泄漏。
- 远程变更仅在本地证据齐全后进行，并记录健康状态和清理结果。
