# 客户端平台与 NAS 部署

## 1. 支持平台与优先顺序

- 客户端目标平台为 Web、安卓和 Windows。
- 优先实现 Web，让用户先通过浏览器体验和使用知识库，不必等待安装客户端。
- Web 需要兼顾电脑和手机屏幕上的基本使用。
- 安卓和 Windows 客户端仍属于目标范围，两者的先后顺序及功能排期尚未确定。
- 安卓桌面 Inbox 控件属于安卓客户端的系统集成能力，不要求首个 Web 版本同时交付。
- 不因选择 Web 优先而自动承诺 macOS、Linux 或 iOS 的独立客户端。

Web 首版限定单用户、单知识库，允许同一用户使用多个设备。完整分层图谱、原生安装版及控件、手机系统推送后续实施，范围见 [Web 首版](./web-first-release.md)。

## 2. 用户自托管

- 服务端部署到用户自己的群晖 NAS，以其 Linux 环境作为目标部署环境。
- NAS 承载 Web 服务、知识库服务与多端同步，以及独立的 AI 知识管理员和记忆整理任务。
- 需求文档中的“云端”在当前部署方案下指 NAS 上的服务端，不要求另行使用商业托管知识库服务。
- 知识库与管理员仍是独立子系统：管理员停止或被替换时，知识库和 Web 基础功能继续可用。
- Web、安卓和 Windows 访问同一知识库服务，遵守统一的权限、版本、路径更新和冲突规则。

“AI 管理员部署在 NAS”不等于要求在 NAS 本机运行大模型。模型服务位置、供应商和具体调用方式尚未选择，不预设 NAS 的推理算力。

## 3. 访问与可用性

- 用户希望在不同地点通过浏览器访问，因此需要设计适合其网络环境的远程访问方式。
- NAS 上部署成功不等于自动具备外网访问能力；远程连接、域名、证书和网络条件在部署设计阶段核对。
- 延续 HTTPS 和账号访问控制要求，不将知识库或 NAS 管理入口默认开放给匿名访问。
- NAS 关机或不可达时，同步及依赖 NAS 的 AI 功能不可用；安卓和 Windows 的已确认本地离线能力继续保留。
- Web 首版支持已缓存笔记离线阅读/编辑、Inbox 新建和本地范围搜索，联网且客户端打开时自动同步；离线结构操作和新附件上传暂不支持。具体状态与浏览器存储风险见 [Web 离线边界](./web-first-release.md)。
- 浏览器不直接获得用户设备上任意文件目录访问能力；首版外部文件编辑检测针对 NAS 原始目录，原生端文件接入后续适配。

## 4. 时间与数据存储

- 每日记忆整理按 NAS 服务所采用的服务器本机时间凌晨 3 点执行，时间可配置。
- 部署时应使任务采用的时区与 NAS 预期的本机时区一致，并明确展示；不因运行环境默认设置而悄悄改变执行时间。
- NAS 上的知识库持久数据使用可直接访问的文件目录保存，程序升级或替换不能清除用户数据。
- 外部备份软件可按完整、标准（`raw` + `derived`）、最小化（仅 `raw`）三档清单备份 NAS 上的实际文件。
- 不要求用户通过 AI 框架或某个专用数据库导出，才能访问和备份原始知识。

## 5. 后续设计时核对

- 群晖具体型号、CPU 架构、内存和 DSM 版本。
- 可用运行环境、安装方式及持久数据目录权限。
- 用户的局域网与外网访问条件。
- 单用户账号初始化、目标浏览器和各客户端最低系统版本。
- 已确定 Web 离线范围的实际可靠性及原生平台适配。

技术方向见[整体架构](../architecture/technical-design.md)：优先 Compose 部署、共享 Web 前端与 Tauri 原生适配；实际 NAS 兼容性和 Agent 框架仍需验证。这些核对事项不阻碍当前设计，也不代表已经安装或部署。
