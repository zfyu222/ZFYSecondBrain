# 笔记双视图需求：思维导图与 Markdown

## 1. 需求背景

用户更习惯通过思维导图编辑笔记，因为层级清晰、适合快速组织想法，并且不需要考虑排版。Markdown 更适合移动端阅读、AI 理解、内容搜索、跨平台流转和后续知识加工。

产品需要同时发挥两种表达方式的优势，但不强制每篇笔记都创建两个视图，也不把两个视图当作相互独立的笔记。

## 2. 核心原则

每篇笔记至少启用一种主要格式，并可以根据内容复杂度和用户需要选择以下状态：

- Markdown 笔记：只有 Markdown 视图，适合简单记录、清单和短文本。
- 思维导图笔记：只有思维导图视图，适合快速记录、组织和理解知识结构。
- 双视图笔记：同时启用 Markdown 和思维导图，两个视图都可以编辑并按需同步。

对于双视图笔记，两个视图是同一份知识的不同表达，不是两篇笔记。用户可以在任意一个视图中编辑，并在需要时同步到另一个视图。

系统不应仅因为 Markdown 包含标题或层级就自动创建思维导图。AI 可以提示某篇笔记适合生成导图，但是否启用由用户决定。

用户可以按需转换笔记状态：

- Markdown 笔记可以通过“生成思维导图”升级为双视图笔记。
- 思维导图笔记可以通过“生成 Markdown”升级为双视图笔记。
- 生成缺失视图时，由确定性转换规则和 AI 共同完成首次转换。
- 隐藏某个视图时保留其数据，并停止该笔记的双视图同步。
- 删除某个视图时需要明确确认；如果该视图包含另一种格式无法完整表达的内容或关系，必须提示可能的数据损失。

## 3. 思维导图节点

启用思维导图后，每个节点至少包含：

- 简短标题：直接显示在导图中，保持导图简洁。
- 详细正文：允许保存多段 Markdown 内容，按需展开查看。
- 节点类型：用于表达标题、观点、正文、待办、引用、代码、图片等语义。
- 层级与顺序：用于确定节点在笔记中的组织位置。
- 来源信息：记录节点对应的 Markdown 原文位置或 AI 生成来源。

创建节点时不应要求用户频繁选择类型。系统提供合理默认值，并允许通过快捷操作转换类型；新建兄弟节点时可以继承前一个节点的类型。

## 4. 节点关系

同一张导图中包含两类连线：

### 4.1 结构连线

- 表示父子层级以及内容的包含或展开关系。
- 默认不显示关系标签，避免增加记录负担。
- 兄弟节点因拥有同一父节点而自然形成并列关系，不需要额外连线。

### 4.2 语义连线

- 用于明确表示知识之间的逻辑关系。
- 可以连接导图中的任意相关节点。
- 关系可以具有方向。
- 用户可以修改 AI 建议的关系，并可按需使用自定义关系。

首批内置 14 种常用语义关系：

| 分组 | 关系 | 规范方向 | 用途 |
| --- | --- | --- | --- |
| 概念 | 定义为 | 概念 → 定义 | 说明概念的含义 |
| 概念 | 属于 | 具体概念 → 上位类别 | 表达分类关系，反向可显示为“包含类别成员” |
| 概念 | 组成 | 部分 → 整体 | 表达部分与整体，反向可显示为“由……组成” |
| 概念 | 例子 | 概念 → 示例 | 表达抽象知识的具体实例 |
| 推理 | 导致 | 原因 → 结果 | 表达明确的因果关系 |
| 推理 | 影响 | 影响方 → 被影响方 | 表达非绝对或方向性的影响 |
| 推理 | 支持 | 依据 → 观点 | 表达证据、理由或论据支持观点 |
| 推理 | 反驳 | 依据 → 观点 | 表达证据、理由或论据反对观点 |
| 行动 | 实现 | 方法 → 目标 | 表达手段、方案与目标的关系 |
| 行动 | 依赖 | 依赖方 → 前置条件 | 表达完成某事所需的条件 |
| 行动 | 先于 | 前项 → 后项 | 表达时间、流程或步骤顺序 |
| 比较 | 相似 | 双向 | 表达两个知识点的共同点 |
| 比较 | 相反 | 双向 | 表达对立、冲突或相反含义 |
| 通用 | 相关 | 双向 | 暂时无法准确分类但确实相关的关系 |

关系选择器按分组展示，并优先显示用户最近使用的关系。自定义关系允许存在，但 AI 应优先映射到内置关系；无法可靠映射时保留原始名称。方向性关系在界面中可以根据阅读方向显示自然的反向文案，但底层只保存规范方向，避免将同一关系重复定义为两种类型。

结构关系和语义关系共同显示在唯一的一张导图中，不生成“结构导图”和“逻辑导图”等多个版本。

## 5. AI 辅助转换

### 5.1 思维导图转 Markdown

AI需要结合节点类型、层级、正文和连线关系，把导图整理成便于阅读的 Markdown，而不是只按照节点深度机械生成标题。

AI可以：

- 判断内容应表达为章节、观点、正文、例子或结论。
- 将节点关系组织成自然的上下文和段落。
- 在不改变原意的前提下拆分、合并或调整表达。
- 将导图中的简短节点扩展为连贯的 Markdown 结构。

### 5.2 Markdown 转思维导图

系统只生成一张融合后的思维导图。AI需要：

- 使用 Markdown 标题作为主要结构参考，但不局限于标题层级。
- 从段落中提取核心概念和关键观点。
- 将长内容压缩成简短节点，并把原文保留在节点正文中。
- 判断原因、结果、观点、论据、例子、结论等逻辑关系。
- 重新组织必要的父子层级，并补充有意义的语义连线。
- 保留节点与原文之间的可追溯关系。

### 5.3 AI 操作边界

- 基础视图转换不应依赖 AI 猜测即可完成的部分，应使用确定性规则处理。
- AI主要处理语义理解、结构整理和关系补充等模糊部分。
- AI不得把推测伪装成用户原始内容。
- AI新增的解释、例子或知识必须与原文明确区分。
- 低置信度关系应标记为待确认。
- 用户确认或手动修改后的结构与关系优先级高于后续 AI 建议。

## 6. 双视图同步

只有同时启用 Markdown 和思维导图的笔记才进行双视图差异检查与同步。双视图不要求实时同步，支持以下两种触发方式：

- 手动同步：用户主动点击按钮，同步当前笔记的两个视图。
- 定期检查：每天检查尚未同步的笔记，并执行允许自动处理的更新。

同步时，系统分别比较 Markdown 和思维导图相对于上次共同版本的变化。变化需要被理解为节点、正文、层级、顺序和关系等语义操作，而不只是文本字符差异。

当两个视图都发生修改时：

- 修改不同内容时自动合并。
- 标题、正文、节点移动和关系变化等互不冲突的操作自动合并。
- 两边同时修改同一内容时，由 AI 尝试合并或交给用户确认。
- 一边删除、另一边继续编辑同一内容时，必须由用户确认。
- 同步产生的更新不得再次触发反向同步循环。

## 7. 自动检查与安全性

- 每日检查由云端定时任务执行，不依赖用户设备保持开机或应用处于运行状态。
- 自动检查可以直接处理无冲突、高置信度且不会造成内容丢失的更新。
- 大规模重组、删除内容或低置信度判断必须等待用户确认。
- 需要确认的内容进入用户的待确认队列，不阻塞其他安全变更。
- 用户下一次打开任意客户端时，应显示待确认提醒。
- 系统可以向用户手机发送推送通知；默认只提示待确认项目的数量和所属笔记，不在锁屏通知中展示敏感正文。
- 同一项待确认内容在不同设备间保持一致状态，避免重复确认。
- 同步结果应提供简短摘要，例如新增节点、调整关系和待确认冲突的数量。
- 每次同步前后都需要保留版本记录，并允许撤销。
- 尚未同步时，界面应提示两个视图各自存在的待同步变化。
- 只有一个视图的笔记不产生双视图同步状态，也不承担相应的 AI 处理成本。

## 8. 当前未决事项

- AI低置信度关系的展示方式和确认流程。
- 双方修改同一内容时，冲突解决界面的具体形式。
- 云端处理笔记时的数据加密、隐私权限和 AI 数据边界。
- 每日任务的执行时间、时区规则和失败重试策略。
