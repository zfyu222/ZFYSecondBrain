# 思维导图与语义关系存储格式

## 1. 核心决定

思维导图相关原始数据拆分为两个公开、可读的明文文件：

- OPML 2.0：保存导图的树状结构和节点内容。
- YAML：保存无法从树结构推导的语义关系。

不使用数据库作为导图或关系的唯一原始存储，也不使用不透明 ID 连接节点。

## 2. 文件组织

用户创作的同一篇双视图笔记在 `raw` 中使用相同基础名称配对：

```text
raw/Areas/健康/睡眠质量.md
raw/Areas/健康/睡眠质量.opml
raw/Areas/健康/睡眠质量.relations.yaml
raw/Areas/健康/睡眠质量.assets/
```

- `.md` 文件在笔记启用 Markdown 视图时存在。
- `.opml` 文件在笔记启用思维导图视图时存在。
- `.relations.yaml` 仅在存在需要单独保存的语义关系时创建。
- `.assets/` 保存图片、视频、音频、PDF 等原始附件；没有附件时不创建。
- 只有一个视图的笔记不创建不需要的空文件。
- `.relations.yaml` 保存用户在笔记内明确创建或确认的关系；AI 从多篇文档中提取的知识图谱关系保存在 `derived/relations`，不与用户原始关系混写。

## 3. OPML 导图树

OPML 文件遵循 [OPML 2.0](https://opml.org/spec2.opml) 基础规范。每个 `<outline>` 元素表示一个节点，嵌套关系表示父子层级，文件顺序表示兄弟节点顺序。

示例：

```xml
<opml version="2.0">
  <head>
    <title>曝光三角</title>
  </head>
  <body>
    <outline text="曝光三角" type="topic">
      <outline text="光圈" type="concept" />
      <outline text="快门" type="concept" />
      <outline text="ISO" type="concept" />
    </outline>
  </body>
</opml>
```

节点信息遵循以下规则：

- `text` 保存节点的简短标题。
- 嵌套层级和文件顺序保存结构与排序。
- `type` 保存标题、观点、正文、待办、引用等节点类型。
- 详细正文以 Markdown 明文保存在有文档说明的节点属性中；不得编码为只有当前客户端能解释的二进制内容。
- 标签可以使用 OPML 的 `category` 属性。
- 跨文档引用保存为可读的知识库路径和标题锚点。
- 视图缩放、临时选中节点等可推导或短期界面状态不属于核心原始数据，可以放入可删除缓存。
- 必须记录本项目使用的 OPML 属性及版本，其他工具忽略扩展属性后仍应能够读取完整树结构和节点标题。

## 4. YAML 语义关系

语义关系文件使用 YAML 明文，并通过节点在导图中的可读路径定位两端：

```yaml
version: 1
map: ./睡眠质量.opml

relations:
  - from: /睡眠不足/食欲增强
    type: 导致
    to: /减脂/速度下降
    status: confirmed

  - from: /睡眠不足
    type: 未明确
    to: /工作状态下降
    status: unresolved
```

关系文件遵循以下规则：

- `from` 和 `to` 使用从导图根节点开始的可读节点路径。
- `type` 使用需求文档中确定的内置关系名称或用户自定义名称。
- 有方向关系按照规范方向保存；双向关系不因阅读方向重复存储。
- “未明确”等状态使用可读枚举值，不使用数据库状态码。
- 跨文档关系使用目标文档的知识库路径加节点路径表达。
- 节点移动或改名时，应用自动重写受影响的关系路径。
- 文件即使脱离当前软件，也应当能够通过标题和路径理解关系含义。

## 5. 数据库与派生数据

数据库可以为 OPML 节点和 YAML 关系建立内部索引，以提高搜索、渲染和 AI 处理速度，但这些索引必须满足：

- 可以从原始文件完整重建。
- 删除后不造成节点、关系或正文丢失。
- 内部索引 ID 不写回原始关系，不成为迁移所必需的数据。
- 云端和客户端均以原始文件内容作为最终可迁移依据。

## 6. 导入与导出

- 可以直接导入符合 OPML 2.0 的普通大纲文件。
- 导入不认识的 OPML 属性时尽量保留原始值，避免静默丢失。
- 导出 OPML 时，其他大纲工具至少能够读取节点标题、层级和顺序。
- 语义关系文件提供公开的字段说明和版本迁移规则。
- 未来可以额外提供 GraphML 等图格式导出，但 GraphML 不作为原始存储格式。

## 7. 当前未决事项

- OPML 节点详细 Markdown 正文所使用的扩展属性名称和转义规则。
- 跨文档语义关系的最终 YAML 字段结构。
