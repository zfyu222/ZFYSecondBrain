# 需求总览与查漏补缺

## 1. 当前结论

产品是一个可独立使用的个人知识库，以及一个可替换的 AI 知识管理员。用户以思维导图组织想法，以 Markdown 阅读、存储和加工知识；原始资料不被当前软件或 Agent 框架绑定。

目标平台为 Web、安卓、Windows，优先 Web，服务端自托管于用户的群晖 NAS。

本文件汇总已有决定，不是开发排期。**已确认需求不等于首版需求，也不等于已经实现。** 当前仍处于文档阶段；本轮不选整体技术栈，不新增实现代码。

## 2. 状态口径

- **已确认**：产品方向和行为已经确定，具体版本归属仍可讨论。
- **进阶想法**：当前不做，保留参考，不承诺下一期或一定实现。
- **已排除或替代**：当前方案明确不采用，不自动放入未来待办。
- **待确认产品问题**：会影响使用体验或首版边界，需要在排期前明确。
- **实现细节**：由设计阶段决定和验证，不要求用户逐项讨论字段、算法和接口。

详细规则以各专题文档为依据；发现真正矛盾时明确列出，不以汇总文档静默改变用户决定。

## 4. 不可被排期或实现细节改变的原则

- `raw` 保存原始笔记、导图、附件和用户模板；`derived` 保存摘要、片段、关系、社区和地图等加工结果。
- 数据库和索引可以替换、重建，不是内容与链接的唯一来源。
- 最小化备份仅含 `raw` 也能打开原始知识；它不保证恢复 AI 结果，包括保存在 `derived` 中的用户修改过的摘要。
- 知识库不依赖管理员运行；所有 AI 理解、推理与生成归管理员，通过受控工具写入。
- 对话历史不是正式知识，不作为事实证据；将新知识写入 `raw` 需要明确要求。
- 事先启用的整理规则只授权对应操作，不能据此把任意对话或推断写进原始笔记。
- 同步、AI 写回、历史恢复和外部编辑均不能静默覆盖较新的并发修改。
- 笔记暂不做应用层加密或端到端加密，但 HTTPS 和账号访问控制仍然保留。

## 5. 暂不做、已排除及未确认想法

### 5.1 已进入进阶想法池

统一见[进阶想法池](../advanced-ideas.md)：

- 专门的冲突 diff 对比界面。
- 用户主动触发的 AI 冲突合并。
- 普通事项提醒、周期提醒和文档回顾提醒。
- 间隔复习及 AI 复习提问。
- 资料导入与批量迁移。

这些不取消基础版本记录、修改 diff 留档、系统通知、原生备份恢复和外部文件变更检测。

### 5.2 已排除或被替代

- 固定格式文档的持续字段校验和布局控制：改为自由模板。
- 产品自行执行整库备份、上传和备份轮换：由外部软件负责。
- 默认互联网问答、聊天事实自动入库：不符合当前知识边界。
- 所有笔记强制双视图、实时双视图同步：不采用。
- 图谱依赖自动拆分原始文档：不是当前知识加工的组织原则。

### 5.3 旧草图或讨论中仍未确认的方向

以下仅记录出处与缺口，不新增首版承诺，也不自动认定永远不做：

- **跨文档矛盾的专项检查与报告**：图谱可以记录反驳、相反等关系，但尚未确认一个独立的定期矛盾清单功能；原始草图有此想法。
- **跨文档内容嵌入、组合阅读或专门拆分合并工具**：当前支持引用和预览，不等于已有持续嵌入或组合文档功能；后续重点转为关系发现。
- **Windows 全局快捷记录、托盘或桌面便签**：此前只是建议，用户具体确认的是安卓今日 Inbox 控件。
- **从其他应用分享进来、网页剪藏等采集入口**：未确认具体范围，不等于普通新建笔记或外部文件编辑。
- **GraphML 额外导出、人工纠错或固定地图关系**：专题中留有候选方向，未决定实施。

这些方向可在需求总览核对时决定忽略、放入想法池或另行讨论，不需要为完整性而全部开发。

## 6. 划分 Web 首版前需要明确的产品问题

| 问题 | 已确定部分 | 尚需明确的边界 |
| --- | --- | --- |
| 首次交付的核心流程 | Web 优先；主要使用者是用户本人 | Web 首版是先完整记录和管理知识，还是同时必须包含导图语义转换、问答、自动加工和图谱？尚未作取舍 |
| Web 离线体验 | Windows/安卓本地优先不变 | 浏览器断网时要支持到什么程度；不能仅因浏览器技术不同就悄悄取消或承诺完整离线 |
| 账号与知识库数量 | 私人 NAS 部署且需要访问控制 | 首版是否限定一个使用者和一个知识库，还是需要多账号、多库；尚未承诺多人协作 |
| 发布可达性 | 希望随时随地通过 Web 使用 | 第一次验收是否要求外网可用；具体网络方案取决于 NAS 和网络条件 |

本节不是要求用户现在一次回答所有问题；下一轮先定核心流程，其余按影响顺序处理。

## 7. 交给设计阶段处理的细节与验证输入

### 7.1 技术选型与数据规范

- 整体技术栈、编辑器、Agent 框架、检索方案、同步协议、索引及运行环境。已有 Markdown 解析方向和 nanobot 候选不等于整体栈已定。
- OPML 正文属性、YAML 字段、重名节点消歧、无标题片段锚定、外部移动识别。
- 同步共同版本和 diff、持久化文件事务、失败恢复、幂等及冲突展示。
- Skill、Tool、工作流、子 Agent 拆分；模型接入、预算控制和关系质量校验。
- 社区聚类算法、加载规模、增量范围和全局检查周期。
- 历史归并、空间管理、模板目录和三档备份清单的具体路径。
- 控件大小、预览字数、更新策略、编辑窗口以及平台版本兼容性。

### 7.2 审核发现的边界条件

- **极短文本摘要**：例如 5 字正文若严格限制摘要为 1/10，无法生成非空整数长度摘要；空文档、极短文本的终止或例外规则需提出方案，不能默默改变已确认比例。
- **历史自动清理**：30 分钟是普通历史恢复点的设计默认值，不是自动保存间隔；回收站保留期尚未确认，不能误用此前提过的 30 天自动清空。
- **归档检索穿透**：排除 Archive 时还要检查派生社区摘要和关联检索的来源，不能通过缓存间接重新引用被排除内容；这属于既有检索边界的实现验证。
- **关系来源与“确认”状态**：区分用户原始导图关系、AI 图谱关系及用户确认摘要的存储与权限；设计规范必须解释“正式 AI 关系”的接受标准，不能强迫无人工编辑的地图逐条人工审批，也不能把不确定关系当成事实。
- **最小化恢复与授权**：只备份 `raw` 不会带回原 AI 结果和整理授权，恢复后不能直接续跑未经重新启用的任务。

涉及放宽用户已确定规则或新增破坏性自动操作时，仍需明确确认；普通字段和性能参数不再拆成产品讨论。

### 7.3 环境信息（进入设计/部署时提供）

- 群晖型号、CPU 架构、内存和 DSM 版本。
- 数据目录及运行权限，可用的外网访问条件。
- 目标浏览器、安卓与 Windows 版本。
- AI 模型服务接入方式和可接受的使用成本。

## 8. 本轮一致性核对记录

- 将旧的省略目录链接示例改为符合已确定知识库根目录的 `raw/Areas/...` 路径。
- 将“AI 捕获内容进入 Inbox”澄清为用户明确要求记录后的写入，避免与默认只读冲突。
- 将双视图转换中“AI 可新增解释或知识”的旧表述收紧为不得擅自添加新知识；明确委托的补充仍须区分来源。
- 核对了延期与保留能力：diff 界面与审计 diff、提醒与系统通知、导入与原生恢复、Web 优先与安卓控件，不是同一范围。
- 本轮没有将未确认想法升格为需求，也没有给全部已确认功能指定首版排期。

## 9. 下一步：形成 Web 首版流程范围草案

建议按可完整验收的使用流程讨论，而不是按页面或框架拆分：

1. 记录、编辑、模板、附件和查找。
2. 分类、引用、移动、归档和安全恢复。
3. 导图编辑及按需双视图同步。
4. 带来源的个人知识问答和明确委托的修改。
5. 授权的每日记忆整理及知识地图浏览。
6. NAS 部署、Web 访问、必要同步和异常处理。

以上是评估清单，不是首版全选清单。用户确认核心流程后，再提出纳入、延期、依赖和验收条件的具体草案；平台兼容性及框架选择在范围明确之后推进。
