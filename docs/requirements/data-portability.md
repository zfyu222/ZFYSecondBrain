# 数据可迁移原则

## 1. 原则

第二大脑中的原始数据属于用户，并且必须能够脱离当前软件、技术栈和云端服务继续阅读与维护。

更换软件或重写系统时，用户不应依赖原系统的数据库、私有接口或不可读标识才能解释自己的笔记和知识关系。

## 2. 原始数据

- 用户原始数据统一保存在 `raw` 目录；AI 加工得到但需要持久保留的数据统一保存在 `derived` 目录。
- 原始笔记、链接、附件引用、思维导图结构和知识关系使用开放、可读且有文档说明的格式保存。
- 用户能够完整导出原始文件，导出结果不是经过简化或丢失信息的副本。
- 任何仅保存在云端数据库中的信息，只要影响笔记含义，就必须能够一并导出为可读文件。
- 不使用只有当前系统数据库才能解析的不透明 ID 表达链接或内容关系。
- 数据格式设计优先考虑长期可读性，而不是绑定某个框架、数据库或供应商。

## 3. 内部链接

- 文档链接使用相对于知识库根目录的可读文件路径。
- 节点或段落链接使用文件路径加标题锚点。
- ZFY Markdown 原文使用兼容 Obsidian Flavored Markdown 的 Wiki Link，例如 `[[raw/Areas/健康/睡眠质量研究]]`。
- 链接到具体内容时使用类似 `[[raw/Areas/健康/睡眠质量研究#睡眠与食欲]]` 的形式。
- 不使用 `^block-id`、`obsidian://` 或必须依赖插件才能解释的链接。
- 系统支持把 Wiki Link 导出为标准 Markdown 相对链接，例如 `[睡眠质量研究](../健康/睡眠质量研究.md)`。
- 文件、目录或标题在应用内改名和移动时，系统负责重写受影响的链接。
- 路径重写必须覆盖 Markdown、OPML、关系 YAML、软链接及其他明文引用，具体规则见[文档移动与路径更新](./path-updates.md)。
- 即使链接失效，用户仍能直接阅读目标路径和标题，并在其他工具中修复。

不使用稳定 ID 的代价是：文件或标题在系统之外被改名后，链接可能暂时失效。产品接受这一取舍，以换取原始数据的可读性和可迁移性。

## 4. 数据库与索引

- 数据库、全文索引、向量索引和缓存只用于提高性能。
- 所有索引都必须能够从原始文件重新生成。
- 删除数据库或更换技术实现后，原始内容和链接仍然完整可用。
- 导出和备份不能只包含数据库快照，必须包含用户可直接访问的原始文件。
- 备份由用户的外部备份软件执行，知识库提供完整、标准（`raw` + `derived`）和最小化（仅 `raw`）三档清单，并支持按实际范围从原生目录恢复；具体边界见[撤销、历史记录与备份恢复](./history-and-recovery.md)。

## 5. AI 派生知识

- AI 提取的观点片段、跨文档关系、知识社区、地图和多级摘要使用明文文件保存在 `derived`。
- 完整备份、标准备份以及要求保留既有 AI 加工结果的完整导出必须包含 `derived`；用户可以明确选择仅备份 `raw` 的最小化方案。AI 输出不是确定性结果，省略 `derived` 意味着放弃恢复其中的既有结果，而不是把它视为可精确重建的缓存。
- 每项派生知识都应通过可读路径和标题锚点指向来源，不使用只有当前系统能够解释的不透明 ID。
- 图数据库和向量数据库可以索引这些文件，但不能成为知识图谱的唯一存储。
- 详细规则见[分层知识图谱与文档地图](./hierarchical-knowledge-graph.md)。

## 6. 思维导图与知识关系

- 思维导图树使用 OPML 2.0 保存，语义关系使用 YAML 明文文件保存，具体规则见[思维导图与语义关系存储格式](./mindmap-storage.md)。
- 两种格式都必须公开、有版本说明且可以独立解析。
- 不允许只把导图保存在无法脱离应用读取的画布状态或数据库表中。
- 系统必须能够仅根据 OPML 和 YAML 原始文件重建导图和关系。

## 7. 验收标准

在不运行当前第二大脑软件的情况下，用户应当能够：

- 使用普通文本编辑器阅读 Markdown 笔记。
- 根据文件路径和标题理解并维护内部链接。
- 将 ZFY Markdown 批量导出为标准 Markdown。
- 复制整个知识库目录完成备份和迁移。
- 使用公开格式解析思维导图及知识关系。
- 删除可重建的数据库和索引后，再次从原始文件恢复系统内容。
- 读取 `derived` 中的明文文件，理解 AI 提取的片段、关系、社区和地图及其原文来源。
