# 知识组织方式

## 1. 核心原则

知识库采用以下组织方式：

> 文件夹提供稳定的大结构，标签和软链接负责多维分类，Inbox 负责暂存未整理内容。

每篇笔记只有一个真实文件位置。标签、软链接、收藏和智能视图只提供额外入口，不复制原始文件。

## 2. 固定顶层空间

用户原始数据统一放在 `raw` 目录，其中固定包含四个系统级顶层空间：

```text
知识库/
├─ raw/
│  ├─ Inbox/
│  ├─ Projects/
│  ├─ Areas/
│  └─ Archive/
└─ derived/
```

四个空间的职责：

- `Inbox`：保存刚记录、导入或尚未整理的内容。
- `Projects`：保存有明确目标和结束条件的阶段性事项。
- `Areas`：保存需要长期维护的领域，例如健康、职业、家庭和学习。
- `Archive`：保存已经结束或当前不再活跃的项目与领域内容。

这四个 `raw` 子目录属于产品的固定知识组织模型，用户不能删除或创建同级的第五种系统空间。`derived` 用于保存 AI 加工得到的片段、关系、社区、地图和摘要，具体规则见[分层知识图谱与文档地图](./hierarchical-knowledge-graph.md)。界面可以本地化显示名称，但原始目录结构应保持明确和可迁移。

## 3. 目录层级

四个系统级顶层空间保持固定，但其下的用户目录不设置硬性层级上限。

用户可以根据实际知识结构继续嵌套：

```text
raw/
└─ Areas/
   └─ 健康/
      └─ 运动/
         └─ 力量训练/
            └─ 计划/
```

目录用于表达稳定的归属层级；标签、软链接、文档引用和知识关系继续用于跨目录的多维分类。产品可以提示目录过深可能降低浏览效率，但不得阻止用户创建、导入或迁移深层目录。

- 原始目录不因层级较深而被自动压平；专门导入功能暂不实现，未来评估时应保留原目录层级。
- 移动或重命名任意层级目录时，统一更新所有受影响的路径引用。
- 界面需要通过面包屑、搜索和目录树帮助用户在深层结构中定位。
- AI 归类优先复用已有目录，不因产品偏好擅自压平用户结构。

## 4. 单一真实位置

- 一篇笔记只有一个真实文件路径。
- 笔记可以通过软链接出现在多个分类或入口中，但不复制文件内容。
- 标签、收藏、最近编辑和智能视图只保存筛选条件或引用。
- 修改任何入口打开的笔记，实际修改的都是同一份原始文件。
- 文件移动或改名时，系统按照数据可迁移原则更新受影响的内部引用。
- 所有移动和改名操作遵循[文档移动与路径更新](./path-updates.md)，不得只移动文件而留下失效引用。

## 5. Inbox

- 新建、快速记录和外部文件变更检测到的未分类内容可以进入 `Inbox`；专门导入功能暂不实现。AI 仅在用户明确要求记录时将新知识写入 Inbox，不自动收集对话事实入库。
- Inbox 中的内容允许暂时没有项目、领域或标签。
- 内容整理后移动到 `Projects` 或 `Areas`；无需继续使用时可以移入 `Archive`。
- 记忆整理可以建议目标位置和标签，但不应在存在歧义时擅自移动文件。
- 记忆整理自动移动明确归类的内容时，必须同步更新全知识库中指向该内容的引用。

## 6. Projects、Areas 与 Archive

- `Projects` 中的内容围绕阶段性目标组织。
- `Areas` 中的内容围绕长期责任和持续关注领域组织。
- 项目结束或内容不再活跃时，原始文件及其专属附件整体移动到 `Archive`。
- 归档不会删除标签、引用、关系或历史记录。
- 指向归档内容的链接仍然有效，并在路径变化时自动更新。

## 7. 标签与软链接

- 标签用于表达主题、状态、属性等可以跨目录复用的分类。
- 同一篇笔记可以拥有多个标签。
- 软链接用于让一篇笔记出现在另一个项目、领域或用户定义集合中。
- 软链接不得产生内容副本，也不得成为理解原始文件所必需的数据库专属记录。
- 标签和软链接的原始信息必须使用可读明文保存。当前原型把软链接作为所属 Markdown Front Matter 的 `soft_links: ["raw/Projects/…"]`，其中每项是额外入口目录而非文件副本或操作系统 symlink；它随所属正文一起移动。完整目录移动及其软链接重写仍属于后续路径事务范围。

## 8. 智能视图

系统可以根据原始文件和明文元数据生成以下动态视图：

- 最近文档
- 最喜爱文档
- 标签筛选
- 多条件组合筛选
- 待整理内容
- 归档内容

智能视图属于可重建的展示结果，不改变笔记的真实文件位置。

### 8.1 最近文档

- 作为固定快捷列表展示用户最近打开或编辑的文档。
- 按最近活动时间倒序排列，最新使用的文档位于最前。
- 打开列表中的文档不会改变其真实目录位置。
- 最近访问记录属于用户使用状态，不是知识正文；可以跨设备同步，也允许用户清空。
- 已删除或无权访问的文档从列表中移除，归档文档仍可正常出现。

### 8.2 最喜爱文档

- 作为固定快捷列表展示用户主动标记为喜爱的文档。
- 喜爱状态是文档的可迁移明文元数据，例如 ZFY Markdown 属性中的 `favorite: true`。
- 取消喜爱只移除列表入口，不删除、移动或修改文档正文。
- 文档移动、改名或归档后继续保持喜爱状态。
- 列表只引用原始文档，不创建收藏副本。
