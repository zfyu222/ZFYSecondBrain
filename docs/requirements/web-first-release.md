# Web 首版范围与离线边界

状态：用户已接受的首版范围；2026-09-02 整理入文档。本文决定交付范围，不表示已经实现。具体行为沿用各专题需求，技术方案见[整体架构](../architecture/technical-design.md)。

## 1. 首版目标

交付一个可以日常使用的双视图笔记软件：在电脑或手机浏览器记录、整理和查找知识，原始文件保存在自己的 NAS；可以离线记录，也可以按需使用独立的 AI 知识管理员。

- 单用户、单知识库，同一用户可以使用多个设备和浏览器，不做多人协作、多库切换、公开注册和分享权限体系。
- Web 优先，同时适配电脑和手机屏幕；保留登录验证和 HTTPS。
- Markdown、思维导图都属于首版核心编辑方式，不把导图延后到完整知识图谱阶段。
- 知识库基础能力不依赖 AI、模型凭据或管理员启动。
- 首版范围是完整交付目标；内部按里程碑逐步开发，不要求首次原型包含全部功能。

## 2. 纳入首版

| 模块 | 交付内容 | 验收重点 |
| --- | --- | --- |
| 笔记编辑 | OFM 兼容 Markdown 编辑与预览；基础导图编辑；可选单视图或双视图；原格式文件获取及标准 Markdown 导出 | 原文可读、原格式可保存，不强制生成另一视图；导出不等于专门的第三方资料导入 |
| 导图操作 | 节点标题、Markdown 正文、增删、层级与顺序调整、折叠；结构线与已有 15 种语义关系及自定义关系 | 可用键盘和触屏操作；兄弟节点不自动解释为因果；OPML + YAML 可重建 |
| 媒体与模板 | 图片、视频、音频、PDF 附件及适用预览；模板作为新文档起点 | 保存原始附件，不承诺任意媒体编码都能播放；不支持时提供文件入口 |
| 分类与查找 | Inbox、Projects、Areas、Archive；任意深度目录；标签、软链接；搜索与组合过滤；最近、最喜爱 | 原文不因多维分类产生副本；默认搜索排除归档和回收站 |
| 引用维护 | 文档和片段引用、预览、反向链接；移动改名更新引用 | 原始文件、专属配套文件与引用一起变更，失败可恢复 |
| 数据保护 | 撤销重做、粗粒度历史、回收站、三档备份说明和原生目录恢复 | 及时保存不等于每次输入都建立历史；恢复不得覆盖其他版本 |
| 同步与外部编辑 | Web 本地保存及联网同步、冲突二选一；NAS 原始目录外部编辑检测 | 不静默覆盖；浏览器不冒充拥有本地任意目录访问权限 |
| AI 管理员 | 个人知识问答、原文引用、明确授权后的编辑；文档上下文及统一管理员入口 | 默认只读、不以聊天或外网作为知识证据；关闭后基础功能仍可用 |
| 双视图转换 | 手动生成缺失视图；对已有双视图按共同版本检查变化并同步 | AI 做语义理解，知识库做校验、写回与历史；真正冲突二选一 |
| 记忆整理 | 授权后的多级摘要、Inbox 分类打标签与移动、双视图同步 | NAS 本机时间默认 3 点、可配置；只处理已同步数据；失败通知与手动重跑 |
| 通知 | 应用内结果、失败和待确认列表，下次打开仍可查看 | 不以推送到达作为任务成功或用户确认的依据 |
| 部署 | NAS 自托管、持久目录、单账号初始化、电脑与手机 Web 访问 | 原始数据不放在易丢失的容器层；远程访问取决于实际网络条件 |

相关规则见[双视图](./dual-view-notes.md)、[组织方式](./knowledge-organization.md)、[恢复与备份](./history-and-recovery.md)、[管理员](./ai-knowledge-manager.md)。

问答首版采用关键词/全文召回、标签与目录过滤、链接邻域和原文片段读取组成的基础 RAG。向量检索不是首版硬依赖；后续根据真实问题的召回质量增加。GraphRAG 随分层知识图谱推进，不能把仅有反向链接称为完整 GraphRAG。

## 4. Web 离线策略

原则：优先保证记录和编辑；不要求首次访问就能离线，也不承诺浏览器关闭后持续同步。

| 操作 | 首版断网时的行为 |
| --- | --- |
| 打开软件 | 此浏览器已成功加载并缓存应用后，可以离线打开；第一次访问需要联网 |
| 阅读与编辑 | 可读写已缓存的 Markdown、导图和已有摘要；未缓存内容明确显示不可用 |
| 新建 | 可以新建 Inbox 笔记；名称冲突在联网后处理，不能覆盖已有同名笔记 |
| 两种视图 | 可以分别编辑已存在的两个视图；AI 生成和语义同步等联网后触发 |
| 本地搜索 | 只搜索本机已有内容，明确标注不是完整知识库结果 |
| 附件 | 查看已缓存附件；未下载文件显示待联网；首版新增附件上传要求联网，失败不清空正文草稿 |
| 目录结构 | Web 离线暂不开放移动、改名、归档和删除等结构操作；联网并处理有关待同步项后再执行 |
| AI | 问答和新加工需要可用的 NAS 与模型服务；不妨碍本地编辑 |
| 恢复联网 | 客户端打开时自动同步；并发冲突保留双方、二选一；可手动重试 |

这是 Web 首版边界，不改变[原生端离线要求](./multi-device-sync.md)。

### 保存与异常

- 界面区分正在保存、已保存本机/待同步、已同步 NAS、同步失败、冲突；本地事务提交成功才显示已保存本机。
- 正文和待上传操作须一起持久化；不能只保存在页面内存中，也不能只等待退出页面时保存。
- 已经保存到本机的内容应能在刷新或重新打开后恢复；尚未完成本地写入的最后输入不能宣称已保存。
- 请求浏览器持久存储，但授权不保证成功；隐私模式、配额不足、用户清理网站数据等限制需要明确提示。
- 不自动清理未同步笔记；提供未同步内容的原格式导出。用户主动清除浏览器数据仍可能丢失未同步内容，不能宣称 NAS 能恢复从未收到的数据。
- 退出登录或切换服务器前提示未同步内容，允许先同步或导出；不能静默删除，也不能把旧服务器的草稿发送到新服务器。
- 同一浏览器多个标签页也视为可能并发的编辑者，不能依赖“单用户”忽略冲突。
- NAS 在线时记忆整理可以继续；客户端断网期间的新编辑只在之后上传才进入处理范围。

Service Worker 依赖安全上下文，NAS 即使在局域网也应使用 HTTPS，不能把开发用 localhost 的例外套用到普通 NAS IP 地址。[Service Worker 与安全上下文](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API)

浏览器存储是本地待同步副本，不是唯一备份；持久存储申请不能消除用户清理数据的风险。[浏览器存储配额与回收](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

## 5. 首版验收流程

1. 登录 → 新建 Inbox → 编辑 → 保存本机 → 同步 NAS → 第二个浏览器打开相同内容。
2. 已打开文档断网编辑 → 刷新恢复 → 联网同步；另一端改同一段时产生可恢复的二选一冲突。
3. 创建导图 → 保存 OPML/关系 YAML → 重开还原 → 按需生成 Markdown；不启用第二视图的文档不承担转换成本。
4. 移动含附件和双视图的笔记 → 所有内部引用仍有效；失败中断可恢复一致状态。
5. 管理员根据原文作答并提供来源；明确委托的修改有历史；关闭管理员后仍可编辑和搜索。
6. 启用整理规则 → 定时处理已同步文档 → 查看结果与待确认项；故障不覆盖新版本。
7. 从独立的 `raw` 副本恢复笔记；从 `raw + derived` 恢复已有加工结果；不自动连接旧同步目标或启用 AI。

## 6. 进入实施前仍需验证

- 群晖型号、CPU、内存、DSM、容器支持与远程网络条件：影响部署，不阻止前端和协议设计。
- 极短文本摘要规则存在数学边界，不能擅自放宽已确认的 1/10 比例；在摘要实现前提出最小例外方案。
- 编辑器体验、离线可靠性、路径事务、Agent 权限隔离：按[技术验证与里程碑](../architecture/validation-and-milestones.md)验证，不把文档调查当作验证通过。
