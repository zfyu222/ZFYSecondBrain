# 安卓今日 Inbox 桌面控件

## 1. 功能定位

在安卓手机桌面提供真正的桌面控件，包含“今日 Inbox”列表和 `New` 按钮。用户不必先进入 App 主界面，即可查看、快速新建和简单编辑笔记；高级编辑再进入完整 App。

本项是知识库基础功能，不依赖 AI。当前只确认安卓控件，不据此推定 iOS 控件、电脑桌面组件或其他分享入口的范围。

## 2. 今日 Inbox 列表

- 展示今日的 Inbox 笔记，读取同一知识库的本地数据，不创建控件专用的笔记副本。
- 每项的展示内容按优先级选择：有标题则显示标题；无标题但有摘要则显示摘要；两者都没有则显示正文开头的一段文字。
- 显示标题继续遵守明确标题优先、无明确标题时使用已有顶层摘要的规则。
- 没有摘要时直接使用正文预览，不为展示控件临时调用 AI。
- 点击某一项直接打开该笔记的简单编辑入口，不要求先进入文档列表再查找。
- 控件支持浏览列表，并根据可用空间截断预览内容，不截断或修改原始正文。

默认细则由设计阶段负责：以手机本地日期作为“今日”，筛选当天新建或导入、且当前仍位于 `raw/Inbox` 的笔记，最新记录优先显示。手机日期规则与服务器凌晨 3 点的记忆整理时区规则相互独立。

## 3. 快速新建

1. 用户点击控件上的 `New` 按钮。
2. 直接出现用于快速记录的文本输入窗口。
3. 用户输入内容，点击“保存到 Inbox”。
4. 将内容保存为 `raw/Inbox` 中的普通 Markdown 笔记，并返回桌面、请求刷新控件列表。

- 不要求先填写标题、标签或选择目录。
- 保存先在本地完成，不等待 AI 生成摘要或网络同步。
- 断网时仍可新建和编辑，联网后按已有规则同步。
- 保存失败时保留输入内容并告知用户，不显示为保存成功。

## 4. 简单编辑与高级编辑

- 点击列表项直接读取原始笔记，允许快速修改文字并保存。
- 保存修改遵守知识库的版本记录与多端冲突规则，不覆盖并发的新修改。
- 需要富文本式操作、附件管理或思维导图等高级能力时，提供进入完整 App 编辑该文档的入口。
- 进入完整编辑时保留当前输入，不因切换界面丢失草稿。
- 对无法用简单文本编辑器完整表达的笔记，不擅自转换或丢弃结构，转交对应的完整编辑器。

## 5. 安卓平台边界

“不进入 App 就能操作”的产品目标是：不经过主界面或完整导航流程，而不是要求应用组件完全不运行。

安卓标准 App Widget 使用受限的远程视图，不支持直接嵌入普通 `EditText` 输入框。因此默认实现方向是：桌面控件承载列表和按钮，点击后直接启动对话框式轻量编辑界面，保存后返回桌面。该界面属于应用组件，不冒充桌面控件内部原地输入。

具体界面技术和平台最低版本留待技术设计；实现时核对目标系统和启动器行为，不承诺系统限制下无法保证的精确后台刷新时间。

平台依据：[RemoteViews 支持的控件](https://developer.android.com/reference/android/widget/RemoteViews)、[控件点击启动 Activity](https://developer.android.com/develop/ui/compose/glance/user-interaction)。

## 6. 更新与验收

- 新建或编辑成功后请求更新控件，展示已落盘的本地内容。
- 同步、归类移动或删除导致 Inbox 成员变化后，控件相应更新；过期入口不能误打开其他文档。
- 日期变化后重新按“今日”筛选；列表为空时保留 `New` 入口，昨日笔记只是移出今日列表，不删除原文。
- 有标题、只有摘要、两者都没有时分别使用正确的预览内容。
- 不打开 App 主界面即可从桌面发起新建和简单编辑，且断网可保存。
- 本次确认的是产品需求，不代表已完成控件实现或已确定整体版本排期。
