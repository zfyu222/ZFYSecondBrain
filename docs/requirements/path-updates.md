# 文档移动与路径更新

## 1. 需求背景

知识库使用可读路径而非不透明 ID 表达内部引用。Inbox 每日整理、项目归档以及用户手动移动或改名都会改变文件路径，因此系统必须同步更新所有受影响的引用。

文档移动不是单独的文件系统操作，而是一次包含配套数据和引用重写的完整事务。

## 2. 触发场景

以下操作都触发路径更新：

- 记忆整理将 Inbox 文档移动到 `Projects` 或 `Areas`。
- 用户手动移动文档或目录。
- 用户修改文档文件名或目录名称。
- 项目或领域内容移动到 `Archive`。
- 思维导图、关系文件或附件目录随主文档移动。

## 3. 更新范围

移动或改名后，系统检查并重写：

- ZFY Markdown 中的 `[[文档路径]]` 和 `[[文档路径#标题]]`。
- Markdown 中的普通相对链接和媒体路径。
- OPML 节点中的跨文档引用。
- `.relations.yaml` 中的跨文档关系路径。
- 标签或用户集合中保存的软链接。
- 多级摘要文件中保存的原文路径。
- `derived` 中观点片段、跨文档关系、知识社区和地图保存的原文路径。
- 记忆整理任务和提醒中保存的文档路径。
- 其他有公开字段说明的明文路径引用。

指向文档内部标题的锚点在只移动文件时保持不变；标题自身被修改时再按照标题引用规则更新。

## 4. 配套文件移动

移动主文档时，位于 `raw` 且属于该文档的原始配套文件作为一个整体处理：

```text
raw/Areas/健康/睡眠质量.md
raw/Areas/健康/睡眠质量.opml
raw/Areas/健康/睡眠质量.relations.yaml
raw/Areas/健康/睡眠质量.assets/
```

- 只移动实际存在的文件，不创建空配套文件。
- 配套文件使用同一基础名称时，主文档改名后同步改名。
- 附件使用相对于文档或附件目录的路径时，整体移动后尽量保持内部相对路径不变。
- 被多篇文档共同引用的公共附件不随单篇文档移动，只更新需要变化的引用。
- `derived` 中的摘要、片段、关系和地图不作为原始配套文件移动，但必须在同一事务中重写来源路径并更新受影响的派生内容。

## 5. 原子性与失败处理

一次路径变更按以下流程执行：

```text
计算目标路径
    ↓
查找全部入站引用
    ↓
生成移动和重写预览
    ↓
移动主文档及专属配套文件
    ↓
重写全部受影响的明文引用
    ↓
验证新路径和引用
    ↓
提交变更
```

- 文件移动和引用重写必须作为一次原子操作。
- 任一步骤失败时回滚到操作前状态，不允许出现文件已移动但引用只更新一部分的情况。
- 记忆整理批量移动多篇 Inbox 文档时，每篇文档独立提交，单篇失败不影响其他文档。
- 失败项保留在 Inbox 或原位置，并通知用户原因。
- 每次路径变更都进入版本历史并支持撤销；撤销时同样反向更新引用。

## 6. 索引与完整扫描

- 系统可以使用可重建的入站链接索引快速找到引用方。
- 索引不是最终依据；执行移动前需要验证索引对应的原始文件内容。
- 索引缺失或疑似过期时，可以扫描知识库中的明文文件重建引用关系。
- 删除数据库后，路径更新机制仍可通过扫描原始文件工作。

## 7. 外部引用与失效链接

- 系统只能自动更新当前知识库内有权限修改的文件。
- 其他知识库、外部软件或已导出副本中的引用无法自动更新。
- 对无法修改的外部引用，系统保留可读的旧路径记录并在操作结果中提醒用户。
- 如果用户绕过客户端直接在文件系统中移动文件，下一次扫描应识别可能的失效引用并提供修复建议。

## 8. 验收标准

- Inbox 文档自动归类后，知识库内部原有引用仍能打开正确目标。
- 主文档、导图、用户关系和专属附件保持配套一致，派生摘要与知识图谱来源同步更新。
- 移动失败不会留下部分完成状态。
- 移动和撤销均不依赖不可导出的数据库 ID。
- 所有被重写的引用仍以用户可读的明文路径保存。
