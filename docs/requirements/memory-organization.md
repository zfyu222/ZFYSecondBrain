# 记忆整理

## 1. 功能定位

“记忆整理”是 AI 知识管理员发起的云端定时处理能力，用于在用户不主动编辑时检查和整理需要后台处理的知识内容。管理员负责规划和调用工具，知识库负责执行受控的文件操作、路径更新和版本记录；两者的完整边界见 [AI 知识管理员](./ai-knowledge-manager.md)。

记忆整理是同一个 AI 知识管理员的定时工作流，不是第二套面向用户的 AI。用户启用某项整理能力时，即对该能力规定范围内的后续定时操作作出持续授权；未启用的能力不得借记忆整理主动修改原始知识库。

当前已确认的任务包括：

- 检查双视图笔记中尚未同步的 Markdown 和思维导图修改。
- 为新增或内容发生变化的文档生成、检查和更新多级摘要。
- 对归类明确的 Inbox 内容自动添加标签并移动到 `Projects` 或 `Areas`，同时完成全库路径引用更新。
- 根据最近发生变化的原始文档增量维护分层知识图谱，包括观点片段、跨文档关系、知识社区和文档地图。

其他整理能力留待后续讨论。

版本范围：Web 首版包含双视图同步、多级摘要和 Inbox 整理；完整图谱增量维护后续实施。通知首版使用应用内队列，手机系统推送后续实现，详见 [Web 首版](./web-first-release.md)。

## 2. 执行规则

- 由云端执行，不依赖用户设备保持开机或客户端处于运行状态。
- 默认按服务器本机时间每日凌晨 3 点执行。
- 当前服务器部署目标是用户自己的 Linux 服务器，任务时区须与其预期本机时区保持一致；“云端”不意味着必须购买独立托管服务，见[客户端平台与 Linux 服务器部署](./platforms-and-deployment.md)。
- 用户可以配置每日执行时间。
- 设置界面应明确显示当前采用服务器本机时间，避免用户误解为设备所在地时间。
- 同一项任务在多个客户端之间只执行一次。
- AI 知识管理员未启用或暂时不可用时，依赖 AI 的整理任务暂停，但不影响知识库的非 AI 功能和已有数据读取。
- 只处理已同步到云端的内容，不等待离线设备；之后上传的新修改在下一次适用任务中处理。
- AI 结果写回前检查来源版本是否变化；已变化时重新检查，不能覆盖较新的用户修改。具体边界见[多端同步与离线使用](./multi-device-sync.md)。

## 3. 处理结果

- 可以安全自动处理的内容直接完成，并记录结果摘要。
- 多级摘要由 AI 在本次任务中按层生成；文档没有用户明确指定的标题时，最顶层摘要同时作为文档显示标题。
- 知识图谱维护优先检查变化文档及其受影响邻域，并逐层更新必要的社区；不要求每天重新处理整张全局图谱。
- Inbox 归类不明确时保留原位置并进入待确认；不得为了清空 Inbox 强制移动。
- 需要用户判断的内容进入统一待确认队列。
- 用户下次打开任意客户端时收到提醒，也可以通过手机推送获知待确认内容。
- 推送通知默认不在锁屏上展示笔记正文。

## 4. 失败处理

- 任务失败后通知用户，并说明失败的任务和时间。
- 当前阶段不设计复杂的自动重试策略。
- 用户可以手动重新执行失败任务。
- 失败不影响下一次计划任务按正常时间运行。

## 5. 数据处理原则

- 当前阶段不实现端到端加密或应用层笔记内容加密。
- 云端和 AI 在执行用户启用的整理任务时可以按需读取笔记原文。
- 笔记仍通过 HTTPS 传输，并受账号访问权限保护。
